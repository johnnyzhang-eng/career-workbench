# 原版 A 的环境光单因素对照

2026-09-25，Godot 4.7 stable，macOS Apple M5 / GL Compatibility。只测试 **A 原版**的 `WorldEnvironment.environment.ambient_light_energy`。实际运行截图与逐次参数输出见 [本地对照页](index.html)、`A0/`、`A1/` 和 [manifest.json](manifest.json)。不引入新素材，不更改 `main.gd`、`room_3d.gd` 或共用 UI。

| 变量 | A0 原版 | A1 实验 |
| --- | --- | --- |
| 白天环境光 energy | 0.36 | 0.24 |
| 夜间环境光 energy | 0.48 | 0.32 |
| 其余 | 同一 A 原版相机、几何、主光、材料、任务 UI、idle 状态与 Godot 后端 | 与 A0 相同 |

这相当于把环境光强度乘 2/3；两时段保持同一个乘数。`ambient_room.gd` 在调用原版 `apply_phase` 后仅乘此值；运行日志 `AMBIENT_ACTUAL` 和 `manifest.json` 均记录了实际参数。

## P0 基线核验

运行脚本先锁定 `main.gd`、`room_3d.gd`、`comparison.gd`、`project.godot` 的 SHA-256，见 manifest。A0 四张截图与旧基线的对照：360×320 昼夜 **PNG 逐字节相同**；1280×720 昼夜图片仅时钟文字区域有差异（原生像素 x=45–77、y=130–151，共 491 个像素），场景和其他 UI 像素相同。旧图与新图不是同一分钟采集，这一差异符合实时系统时钟；这些截图不能用于比较时钟 UI。新一轮 A0/A1 同尺寸截图用相同脚本顺序采集；真实时间标题仍可能不同。

四个组合每版均成功启动、截图并正常退出，8 个日志无 `SCRIPT ERROR` 或 `ERROR:`。逻辑 360×320 的 PNG 是 720×640，逻辑 1280×720 的 PNG 是 2560×1440，display scale=2；不能将原生 PNG 的显示宽度当逻辑小窗尺寸。只检查了 idle 静帧，尚未验证任务动作或长时间性能。

## 实际视觉观察（未选优）

- 白天全窗：A1 左墙更暗、背光面压低，地板和人物朝光面相对更突出；书桌、角色、阴影轮廓位置保持一致。小窗原大下差异较轻微。
- 夜间全窗：A1 左墙、地面和人物背光面进一步变暗；桌面、人物轮廓仍可辨。小窗原大下未见足以单独决定偏好的改善。
- 环境光变化不能解决角色仍为基础几何、坐姿/键盘接触缺失、屋内材质单一的问题。这些工作按 [3D 改造计划](../3D_QUALITY_PLAN.md) 后续独立处理。

结论边界：代码与截图证明“一项光照参数变动产生这些明暗变化”，**不证明 A1 比 A0 更好**，也不证明 B 原实验的问题只来自环境光。选择须让用户按逻辑小窗和完整应用实际画面评审；如果继续实验，下一项仍须单独开变量。

## 重跑

从仓库根目录执行 `python3 prototype/comparison/run_ambient_experiment.py`。脚本只调用本机 Godot，顺序启动八次真实应用窗口，保存截图、日志和参数清单；不会调用付费 API。运行期间不要手动操作窗口或并行启动另一组截图采集。输出会覆盖本目录同名实验文件。
