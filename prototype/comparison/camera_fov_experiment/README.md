# 原版 A 的相机视野单因素对照

2026-09-25，Godot 4.7 stable，macOS Apple M5 / GL Compatibility。[本地审图页](index.html)可切换逻辑 360×320、1280×720 与昼夜。实际运行截图、日志和 [manifest.json](manifest.json) 均在本目录。原版 `main.gd`、`room_3d.gd`、共用 UI、光照、几何、材质都未修改；不叠加环境光或主光角度实验。

| 参数 | C0 原版 A | C1 实验 |
| --- | --- | --- |
| 透视相机 `Camera3D.fov` | 45°，保持原值不写回 | 41° |
| 相机位置 | (7.5, 6.2, 9.0) | 同 C0 |
| 主光方向/强度 | 原版 −55°/−32°/0°；day 0.65、evening 0.35 | 同 C0 |
| 环境光强度 | day 0.36、evening 0.48 | 同 C0 |
| 场景/UI/状态 | A 原版、idle | 同 C0 |

最初曾试 38°，发现逻辑 360×320 下地板前缘贴近场景底边，存在裁切风险；因此最终只保留 41° 的八张正式对照图，不把 38° 作为候选。运行日志的 `CAMERA_ACTUAL` 验证最终 FOV、相机位置和昼夜光强。K0/A0 的任何参数更改都没有进入此实验。

## 基线和运行校验

采集脚本锁定原场景、共用 UI 和项目配置四个源文件的 SHA-256，值与前两轮的 A0/K0 一致。C0 的 360×320 昼夜 PNG 与第一轮 A0 **逐字节相同**；1280×720 昼夜仅实时系统时钟文字区域不同，各 520 原生像素，边界 x=87–119、y=130–151，其他像素相同。时钟差异不属于相机实验。

C0/C1 × 两尺寸 × 昼夜共八次真实 Godot 窗口采集成功退出；日志无 `SCRIPT ERROR`/`ERROR:`，最终参数核查通过。逻辑 360×320 对应 720×640 PNG、逻辑 1280×720 对应 2560×1440 PNG，display scale=2。这里只测 idle 静帧，不代表角色动作、窗口缩放过渡、长时间性能或不同显示器已经验收。

## 视觉观察（供审图，不选优）

- 41° 把人物、桌/电脑和房间整体放大；在 360×320 逻辑原大中角色脸和电脑的像素占比有所增加。光影、几何和 UI 未改。
- 360×320 的昼夜画面仍显示房间两面墙、地板前缘、书架及桌椅，没有观察到对象被画面边界截断；但地板前缘靠近场景底边，余量不宽。全窗亦未见房间轮廓被裁切。
- 单靠 FOV 不能让角色从静止站立变成能表达“电脑工作/阅读”的动作，也不能提高模型、材质和家具细节。主观舒适度应由用户看小窗原大和完整应用后判断。

当前只证明改变 FOV 能扩大画面中的房间与人物。它是否比原版更适合作常驻小窗，仍待用户审图；小窗边距、热点可点击性、实际动作与窗口缩放过渡仍需单独验收。原版 A 继续作为未合成改动的基线。

## 重跑

从仓库根目录运行 `python3 prototype/comparison/run_camera_fov_experiment.py`。脚本只调用本机 Godot，顺序启动八次真实应用窗口，覆盖本目录同名截图、日志和 manifest；不调用付费 API。不要与其他取证脚本并行。
