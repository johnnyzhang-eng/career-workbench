# 3D 房间与角色质感提升：可执行对照方案

状态：2026-09-25 研究与制作 brief；没有修改运行场景，没有给新路线验收 PASS，也没有采用外部资产。此文档服务于原 3D 路线的下一轮实验，不代表首版美术定稿。

## 证据与判断边界

本轮直接读取 `../godot/main.gd`、`../godot/comparison/room_3d.gd`、`../blender/build_lamp.py`、`../godot/project.godot`，查看同批次实际运行的 `evidence/baseline-*` 与 `evidence/3d-*` PNG，逻辑尺寸分别为 360×320 和 1280×720。本机截图为 2× 原生像素。画面中 A 的书桌、人物与地面有明显的定向投影，B 的细节数量更多，但阴影层次和材质区分减弱；这与用户认为 A 的光影更真实、B 显粗糙的反馈一致。**不能仅凭这四张画面断定单一原因**：B 同时改了光、相机、颜色和几何。

源码可核对的差异：A 使用透视相机、FOV 45°，白天主光能量 0.65、环境光 0.36；B 使用正交相机，白天主光 0.42、环境光 0.65，并额外加 0.22、无阴影的定向补光。B 还重着色左墙与地毯、移动椅子、加地板线和人物脸部/衣服零件。`main.gd` 的房间和角色主要由 BoxMesh、SphereMesh、CylinderMesh 构成；材质工厂默认 roughness=1，只有桌灯是可重建的五部件 Blender GLB。项目配置为 Godot GL Compatibility。当前人物的“工作”动作是整个角色在空间中平移/旋转并摆动单侧手臂，缺坐姿、键盘接触和骨骼变形验证。这些是代码事实，不等于已证实的视觉因果。

参考视频的 [实际画面复核](REFERENCE_FRAME_RECHECK.md) 只确认若干关键帧：06:58 的特征提取与三视图要求、07:13 静态 Blender 模型且尚未绑骨、10:42 修订模型后要求绑骨/权重/桌椅设备/动作、12:42 编辑器内逐物检查、13:19 可见变形问题、15:32–15:47 现有资产与 UI 参考合入 Godot、17:14 表情状态、18:15 可编辑对白及主页/角色设置/日目标讨论。本轮没有顺序重看整条视频，也没有取得逐字提示词全文；下面的 brief 是**本项目自行拟定**，不能标成视频原提示词。

## 制作方式：从提示到可编辑资产

给美术/建模 agent 的自拟 brief：

> 为一个常驻桌面角落的真实目标执行游戏，设计原创成年大学生角色与可剖开的学生房间。角色可在 360×320 逻辑窗口中辨出头、衣服、双手和正在做的事；在 1280×720 中细节经得起看。先提交正、侧、背三视图和中性站姿比例图，列出配色、发型/衣服可替换部件和动作接点；待视觉评审后再建 Blender 母版。房间保留 A 原版的温暖定向光与清晰投影，以桌/电脑、书/阅读区、休息区形成可读行为。先交静态可编辑 `.blend` 与 glTF/GLB、来源清单、导入 Godot 的同尺寸截图；再做骨骼权重和动作。任何阶段都不能用“看起来完成”替代正/侧/背、坐姿、接触点、昼夜、缩窗验收。

Blender 流程建议：blockout 固定镜头和比例 → 编辑可控拓扑（角色肩/肘/膝预留变形环）→ 桌椅等硬表面倒角及法线 → 材质与贴图预算 → rig/权重 → 动画 → glTF/GLB 导入 Godot → 固定镜头截图与动作帧核对。Blender 官方文档说明 Bevel modifier 可非破坏性倒角，并可与 Weighted Normals 配合；Godot 官方导入配置列明法线、UV、skin/animation 选项，不能假设 Blender 编辑器效果会原样传进引擎。参考：[Blender Bevel](https://docs.blender.org/manual/en/latest/modeling/modifiers/generate/bevel.html)、[Godot 导入配置](https://docs.godotengine.org/en/stable/tutorials/assets_pipeline/importing_3d_scenes/import_configuration.html)。

## 同尺寸 A/B 对照：能否真的比 A 好

先做 **A0 原版**、**A1 仅光影调整**、**A2 A1 + 一个精修桌椅**、**A3 A2 + 静态角色母版**、**A4 A3 + 坐姿/读书/键盘动作**。每一步从上一份参数化副本生成，保留 A0；不要再把同时改光、相机、颜色、几何的 B 当成单因素答案。B 保留作历史对照。若要比较正交相机，把它放在另一个仅改投影与匹配角色像素高度的镜头试验里。

每版固定：同一三项虚构任务、同一角色身份、桌/电脑/日历位置、相机、缩放、动画相位、时间相位与角色状态；采集 360×320、800×600、1280×720 的 day/evening，记录逻辑尺寸、原生 PNG 尺寸、display scale 和截图 hash。至少另录 idle→明确开始→电脑/书本动作→暂停→恢复→结束 的真实运行短片。检视时先以**逻辑尺寸原大**看 360×320，再看全窗，不能放大小窗图后判断细节；两位评审分别写“可辨行为、接触阴影、人物与背景分离、舒适度”与具体画面位置。脚本运行和资源检查沿用 [QUALITY_GATE.md](QUALITY_GATE.md) 的 Q01–Q12；新的资产须特别检查 Q01/Q06/Q07/Q11/Q12。若 A1 不比 A0 稳定，回到 A0 逐项调整，不把 A2 的新增细节误认为光照改进。

最小通过条件：在小窗中不读文字也能区分“电脑工作/书本学习/休息/未知”，活动来源与 UI 状态一致；日夜都能看到角色轮廓及脚、椅、桌的空间接触；全窗无明显穿模、变形或材质崩坏；无来源不明资产；连续空闲性能与窗口行为达到现有 Q12 的实测口径。**这些条件目前未验收通过。**

## 留给用户的美术选择

待首件对照可看后，只需用户定：角色更接近有纹理的生活模拟，还是保留现有 Q 版的柔和比例；房间是否接受写实道具与 Q 版角色混搭；小窗优先“能一眼识别行为”还是“最大化室内细节”。这三个是偏好问题，不阻塞上述 P0/P1 和资产管线准备。

## 本轮决策自检

测量链：截图和代码是同一 worktree，但 A/B 相机、光、材色、几何同时不同；本轮只据此提出**隔离实验**，不宣布因果或模型胜负。机制：主光/环境光比与无阴影补光可能解释阴影变浅，正交投影可能解释空间感变化；逐项关/开才可区分。反向检查：即使偏好 A，也要允许 A1/A2 在真实原尺寸截图中超过 A，不能因为“原版更真实”的先验拒绝成功样本。参考 [Godot 渲染器功能表](https://docs.godotengine.org/en/stable/tutorials/rendering/renderers.html) 与 [Godot 光与阴影](https://docs.godotengine.org/en/stable/tutorials/3d/lights_and_shadows.html)：Forward+ 才有部分高级接触阴影/间接光能力，Compatibility 仍支持基本光影；选择须由真实桌面性能决定。
