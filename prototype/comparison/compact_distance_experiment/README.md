# 原版 A：仅小窗相机距离的构图实验

2026-09-25，本机 Godot 4.7 stable、macOS / GL Compatibility。这里不是旧 [41° FOV 试验](../camera_fov_experiment/README.md)的改名：相机**始终是 45° 透视**，目标始终为 `(0, 1.25, 0)`，只在 360×320 小窗把原相机到目标的距离乘以 `0.93`。1280×720 全窗始终乘以 `1.0`。材质、光、角色几何、场景/UI 和虚构任务来自同一原版 A 源码，没有改动。

[原大并排审图页](index.html)提供 day/evening 的 360×320 逻辑尺寸对照；仓库中的 PNG 是 Retina 原生 720×640。`P0` 是原版距离，`P1` 是 93% 距离。每个变体另有 1280×720 / 2560×1440 全窗截图、真实 Godot 日志与 [manifest.json](manifest.json)。采集脚本从同一 worktree 顺序启动八次真正的应用窗口，均成功退出；小窗另外点击了电脑与日历热点，并跑完原虚构结果阻断/记录流程。

| --- | ---: | ---: |
| 人物头顶到脚底投影高度 | 33.02 px | 35.74 px |

以上投影是相机把同一世界坐标头/脚和地板角投到 SubViewport，再换算为**逻辑**像素；不是从抗锯齿截图里猜人物色块边界。地板数据只量几何角点，**不包括板厚或阴影**。昼夜几何数值相同。P1 白天/夜晚原大截图中房间轮廓仍可见，但地板前缘已经贴近画面底部，不宜继续凭这个参数放大。先前试探的 `0.82` 令前右角投影为 y≈148.6，超出 141 px scene 高；`0.90` 的角点 y≈138.1，也使板厚靠近/触及底边，因此正式 P1 选 `0.93`。这些试探没有作为 P1 图片混入。

全窗 P0/P1 的人物投影高度同为 128.79 px；昼夜两组的**场景矩形像素 SHA-256 分别完全相同**，排除了只看参数日志却意外改变全窗渲染的情况。小窗 P0 的昼夜 PNG 又与旧 45° FOV 实验 C0 的对应原版 A PNG **逐字节相同**，作为取证控制样本。四组小窗的电脑/日历按钮矩形相同，实际点击均打开对应交互；按钮是 UI 覆盖热区，不是把 3D 物体碰撞投影当可点区域。

## 可读性判断

P1 的人物面部与服装在小窗里略大，能提高待机人物的辨认余量；原大的日夜两组都有此效果。**它没有让“在电脑前工作 / 读书 / 休息”三种行为一眼可分**：A 版只有待机到电脑方向的简化移动，没有独立的读书、休息角色姿势与物体接触动作；相机距离不能生成这些缺失的线索。按脚本帧数采集的 `started` 图也不适合作动画完成度证据。若继续追求行为可读性，下一独立变量应是角色动作/交互资产，而非把 93% 再缩小并挤掉地板边距。本实验不决定 2D/3D 路线，也不替换正式 A。

## 复现与审查

先在新 worktree 运行一次 Godot 编辑器导入，再从仓库根目录执行：

```bash
/Applications/Godot.app/Contents/MacOS/Godot --headless --editor --path prototype/godot --quit
python3 prototype/comparison/run_compact_distance_experiment.py
python3 scripts/check_privacy.py
```

脚本检查八次截图尺寸、最终 45°、相机距离、热点点击、无脚本错误，并把全窗场景矩形解码为 RGBA 后做像素哈希对照。`manifest.json` 记录四个原版基线源码的 SHA-256；与旧 FOV 试验 C0 使用的四个源文件 SHA-256 一致。日志只含虚构任务和本机参数，路径已脱敏。不要把截图当真实求职结果、动作精修验收或长期常驻性能证据。

仓库当前 `scripts/check_privacy.py` 的分享白名单不包含整个 `prototype/`，因此它对既有和本轮 prototype 文件统一输出 `REVIEW not_in_share_allowlist`，不能解读成“隐私扫描 0 命中”。本轮另对新增文本/日志人工查了身份、凭证及绝对用户路径；20 张新 PNG 仅含 IHDR、sRGB、IDAT、IEND chunk，没有文本或 EXIF；Git diff 和元数据仍须在外发前复核。

决策自检：测量链用旧 C0 原图验证 P0，用引擎投影量角色和地板并以真实截图复核；相机距离与 FOV 作用机制不同，不把旧 41° 结果套为本轮结论；尽管“角色变大”符合预期，仍用全窗逐像素对照、底边余量和点击回归检查代价。下一次有价值的验证是**固定这个构图**再做真实电脑、阅读、休息动作的原大动态验收。
