## 比较对象与固定条件

| 项目 | 固定条件 |
| --- | --- |
| 四种模式 | 原 3D 对照、改良 3D、原创等距 2D、低分辨率最近邻像素化 2D 研究 |

| 尺寸/时段 | 逻辑客户区 1280×720、800×600、360×320（本机 Retina scale=2，原生窗口/PNG 分别为 2560×1440、1600×1200、720×640）；day/evening 共 6 组，每组四种模式，共 24 张运行画面 |
| 截图条件 | 固定任务状态、日夜模式、动画相位、缩放和相机；标明逻辑尺寸、原生窗口像素、原始 PNG 像素、系统显示缩放及版本；截图预览按 1/scale 展示才对应目标逻辑尺寸，不能把 720×640 PNG 原像素展示当 360×320 小窗验收 |

原 PR #19 的原样截图保留为历史证据。若它与本轮三任务 fixture、角色服装或 UI 不一致，应明确写“历史基线，非等条件比较”；只有接入统一包装的原 3D 渲染才参与横向判断。保留原实现的版本引用，不覆写历史证据。

像素化研究应记录内部渲染分辨率与最近邻倍率、是否整数缩放。低分辨率渲染可测试紧凑轮廓及成本，但不等于经过逐像素设计的成熟像素美术。任务文字保留共用高分辨率 UI，不能因缩小场景而一起变得不可读。

本轮不是 Sol vs Astra 受控实验：模型、提示、资产、改动时间与修正预算未分别控制。不得据本轮画面推断模型胜负。若后续做模型实验，需同 brief、同起始提交、同预算与验收脚本，单独记录每次修改和审阅结果。

## 默认小窗与完整应用：必须实际对照

#20 评论与最新用户澄清要求默认小窗、可收起/透明/遮挡试验和完整应用实际对照。逐项记录默认启动尺寸、右上角定位、房子图标→小预览→展开面板→完整工作台、恢复后的同一任务状态。透明度变化须同时检验文字/角色可读性与鼠标命中，透明像素不能被直接视为点击穿透。比较桌面层、普通窗和置顶浮窗；窗口被其他应用覆盖后应可恢复，不能因隐藏/展开触发完成或处罚。最终应在 Codex、浏览器、全屏、Mission Control、双显示器实测遮挡、焦点、透明区域鼠标穿透和恢复行为。当前 360×320 客户区仅证明小窗布局；若没有真实跨应用试验，应列“未验证”，不能声称已实现桌面伴随、系统级置顶或点击穿透。双显示器环境缺失时如实写未测。

## 路线决定与缺陷记录

先检查 Q01–Q11 的阻断项，再比较 Q12、角色身份、UI 融合、昼夜层次、动作和每次修复耗时。记录格式：`模式 / 尺寸 / 时段 / 任务状态 / 缺陷 / 严重度 / 证据 / 修复耗时 / 复测结果`。阻断包括信息错误、关键文字不可读、无法完成任务、未知素材许可；仅影响美感的缺陷也须具体到物体、轮廓或画面区域。

路线建议需写清已看哪些运行画面、未测哪些项、每项修复成本。可建议继续打磨候选，但没有交互与性能证据时不宣布最终路线。用户仍需判断陪伴感与成品质感；本轮不替代 G1 的秋招/CET6 一周体验评审。

## 高分屏测量链纠正

2026-09-24：旧版把 `DisplayServer.window_set_size` 的物理像素参数当作逻辑尺寸，本机 scale=2 时旧 360×320 原生窗口实际约为 180×160 逻辑尺寸。此前截图尺寸与文件名一致只证明像素，不证明屏幕上的目标尺寸。旧截图的可读性/占屏大小/性能结论暂停作为验收依据；24 组矩阵、交互、桌面、性能均须使用新口径重跑。

修正实现以 `logical_size` 为布局依据，`content_scale_size` 保持逻辑尺寸，原生窗口设置为逻辑尺寸乘 `display_scale`；普通场景 viewport 同样按显示倍率渲染，像素研究仍采用较低内部逻辑分辨率。对每批运行核对 JSON 的 `viewport`（逻辑）、`window_pixels`（原生）、`display_scale` 和 PNG 文件头；实际窗口截图确认系统显示大小，点击证明需与同批日志对应。跨显示器倍率变化另测。字体字号仍按逻辑口径，无新字体资产。
