# 原版 A 的主光俯仰角单因素对照

2026-09-25，Godot 4.7 stable，macOS Apple M5 / GL Compatibility。[本地审图页](index.html)可切换逻辑 360×320、1280×720 与昼夜；实际运行截图、日志及 [manifest.json](manifest.json) 均在本目录。不修改原版 `main.gd`、`room_3d.gd` 或共用 UI；不叠加上一轮 A1 的环境光设置。

| 参数 | K0 原版 A | K1 实验 |
| --- | --- | --- |
| 主 DirectionalLight3D `rotation_degrees.x` | −55°，保持原变换不写回 | −65° |
| 主光 yaw/roll | −32° / 0° | 同 K0，运行浮点误差 <0.001° |
| 主光 energy | day 0.65 / evening 0.35 | 同 K0 |
| 环境光 energy | day 0.36 / evening 0.48 | 同 K0 |
| 相机、几何、材质、UI、状态 | A 原版 / idle | 同 K0 |

设置 K1 时只赋值灯光变换的俯仰角；K0 则不重新写入相同角度，以避免欧拉角重新计算带来的像素微差。每次运行日志的 `KEY_LIGHT_ACTUAL` 记录 pitch/yaw/roll、主光 energy 和环境光 energy；脚本核查最终阶段数值。

## P0 基线与采集验证

`run_key_angle_experiment.py` 锁定原场景、共用 UI 和项目渲染配置四个源文件的 SHA-256，见 manifest。与上一轮 [A0 冻结图](../ambient_experiment/README.md) 比较：K0 的 360×320 昼夜 PNG **逐字节相同**；1280×720 昼夜仅系统时钟位置不同，各 269 原生像素，边界 x=104–119、y=130–151，其余像素相同。系统时钟是真实时间，不能用其差异评价场景。

K0/K1 × 两尺寸 × 昼夜共八次真实 Godot 窗口采集均成功退出，运行日志无 `SCRIPT ERROR`/`ERROR:`；参数核查通过。360×320 逻辑窗口输出 720×640 PNG，1280×720 输出 2560×1440 PNG，display scale=2。只测 idle 静帧；动作、夜间连续观察、性能与不同显卡未验收。

## 视觉观察（不宣布优胜）

- K1 的人物投影缩短，并比 K0 更靠近脚；桌椅阴影方向/落点也改变，墙上的书架/窗影变短或移动。全窗原大下变化清楚。
- 360×320 逻辑原大下能看到人物旁的暗块形状变化，但脚与投影的接触点太小，**无法据这组静帧肯定脚下更贴地**。阴影靠近身体也可能降低小窗中轮廓分离。
- 白天与夜间均保留角色和家具可辨性。它没有解决角色造型、坐姿和手与键盘接触缺失的问题。

这是主光**方向**与投影变化的证据，不是“方向 −65° 更精美”的结论。用户可先在逻辑小窗和全窗下看相同画面；若继续，最好用相同角色动画相位观察脚落地时的投影，再决定要不要保留这个角度。

## 重跑

仓库根目录运行 `python3 prototype/comparison/run_key_angle_experiment.py`。脚本只调用本机 Godot，顺序启动八次真实应用窗口，覆盖本目录同名实验文件；不调用付费 API。采集时不要手动操作窗口，也不要与其他取证脚本并行。
