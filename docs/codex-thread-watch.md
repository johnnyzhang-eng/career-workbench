# 可选试验：边使用 Codex，边检查对话信号

同学的默认入门流程不启动这个试验，也不需要小屋子。使用者明确要求监测后，才登记自己的对话文件。这里提供一个标准库检查器和有界复核协议；自动建聊、改入口、完成任务与归档都未实现。

## 两层检查

本地检查器每 15 秒读取登记文件的新记录，不调用模型或网络。初次扫描建立基线，之后保存字节游标；重启沿用游标。它验证文件的会话 ID，只把回合状态、最近一次请求的输入 token、窗口大小、压缩次数和时间写进本机报告。解析登记日志时会接触其中正文，但正文、工具参数/结果、标题、文件路径不会进入报告或游标状态；配置中的路径仍需留在自己的 `private/`。

低频语义复核可用 Codex 当前对话的 heartbeat，建议试验从每 15 分钟开始。每次启动模型仍有消耗，并非零 token；只读小报告、游标与短交接，发现相关变化才读对应对话的最近一个回合。heartbeat 要由使用者明确要求，通过客户端 automation 工具创建；本脚本不会偷偷安排定时模型调用。没有变化保持安静，运行中的任务不打断。脚本正常但 heartbeat 未启用时，只会留下本地报告。

## 指标的含义

`last_input_ratio` = 日志最近一次请求的 `input_tokens` / 日志报告的 `model_context_window`。它不是实时精确上下文占用，也不是对话质量评分。试验默认 0.8 提示保存交接，可调；这个阈值没有用户效果数据支持。累计用量反复计入历史，不能用于这个判断。压缩事件清空旧指标，等待下一次有效样本；读不到、格式不符、身份不符时标未知，不沿用旧健康数值。

`task_complete` 是本地日志里的回合事件名称，绝不作为人的任务完成证据。`completed_turn_id` 仅让复核器知道哪一回合出现了新结果。任务完成仍需要当前阶段目标、验收条件、实际产物和未完成范围一致；本人作答、AI 解答和外部回执要区分。没有更新不能推断停滞或失败。

适配器基于本机观察到的 JSONL 格式，**不是官方稳定接口**。不同版本/主机可能没有这些文件或字段。官方 [App Server](https://learn.chatgpt.com/docs/app-server) 提供 token 和回合事件，但不代表可订阅现有桌面客户端的全部事件；官方 [自动压缩配置](https://learn.chatgpt.com/docs/config-file/config-reference)也不能等同于自动另开对话。本试验不改 Codex 配置、不安装全局 Hooks。

## 明确登记、启动与停止

先由自己的 Codex 确认所选任务对应的本机日志路径；不扫描其他人的 `private/`，不把整个日志目录当任务来源。将以下虚构配置保存为 `private/thread-watch/config.json`，路径用本机已核对的绝对路径替换：

```json
{
  "input_ratio_threshold": 0.8,
  "tasks": [
    {"task_id": "T01", "thread_id": "fictional-thread-id", "rollout_path": "/ABS/LOCAL/SELECTED-ROLLOUT.jsonl"}
  ]
}
```

```sh
python3 scripts/codex_thread_watch.py --config private/thread-watch/config.json --workspace private/thread-watch
python3 scripts/codex_thread_watch.py --config private/thread-watch/config.json --workspace private/thread-watch --watch --interval 15
```

一次运行打印报告；持续运行只打印变化版本和任务数量，报告在 `private/thread-watch/report.json`。放在自己的后台终端运行，用 Ctrl-C 或终止自己的进程停止；不会自动随电脑开机重启。新增阶段需手动核对并更新配置，脚本不自行发现对话。停止 heartbeat 也应通过客户端的 automation 工具暂停/删除。

日志截断或替换时重新建立基线；部分行下次再读，格式错误不跳过未知事件冒充正常。扫描锁防止并发覆盖；异常终止留下锁时，先核对锁中 PID 已不存在再删除自己的 `scan.lock`。报告 `as_of` 超过两分钟则视为监测离线，语义复核不根据过期指标操作。报告不是任务总清单，不能覆盖本人事实。

## 复核与续接规则

总览自身的复核回复不能再次触发“有新任务结果”：忽略它自己的回合完成，只检查压力或来源异常变化。初次报告中的旧回合建立基线，不补发一串历史提醒。单条记录读取上限为 16 MB，超过时来源标未知；先核对适配器兼容性，不能据此判断任务停滞。

[状态图](thread-watch-flow.html)用实线表示本地观察与复核流程，虚线表示尚未实现的自动操作。推荐给 heartbeat 的通用提示词：

```text
仅监测本人已明确登记的任务，不扩展到其他聊天。
先读 report.json 与上次复核游标。过期/读不到时只标未知；首次建立基线，
历史已结束回合不当作刚发生。无变化不读完整聊天、不发例行状态。
发生新回合结果或需要交接时，先看本任务当前交接及总清单来源版本；
需要时只读对应最近一个回合，再按引用核对必要产物。对话正在运行则延后。
最近一次输入比率只是提示，压缩不是任务失败。回复结束不是任务完成。
确有阶段结果才建议更新本任务短交接；验收证据不足标待核对。
需要新入口时先准备短交接，保留历史。没有明确建聊/归档请求时只提出建议；
不得自动关闭任务或改其他任务状态。复核完成后保存自己的游标，保留待核对项。
只有需要用户决定、验收完成、明确阻塞或有实质交接问题时通知。
```

后续自动续接仍需要保存并核验交接 → 新对话恢复核对 → 更新唯一入口 → 保留旧历史的完整验收。这个检查器只实现观察层，不能将“发现压力”直接连到“创建/归档”。

## 如何验证是否有帮助

虚构测试覆盖累计用量误判、压缩作废指标、活动回合、部分行、缺失/替换/截断、错误身份、并发锁及正文不落库。真实使用试验另外记录：是否收到新增事件、误提醒、漏掉的阶段交接、短交接能否恢复下一步、语义复核次数及其可取得的用量。真实值留本机；公开只提供通用发现或虚构复现。短期正常运行不证明长期效率提高，当前没有 token 节省比例。
