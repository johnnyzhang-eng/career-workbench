# 这套方法哪里闭环，哪里还需要补

这一页区分“Codex 对话协作方法”和“小屋子软件集成”。方法可以先用；软件的各个草稿分支需要独立验收，不能把合并文档称作全部产品交付。

| 环节 | 当前交付 | 尚需完成的检查或能力 |
| --- | --- | --- |
| 收集本人事项 | 渐进访谈、领域查漏、未知和来源记录、空清单 | 新用户是否无需作者讲解就能整理自己的事项；有待补领域时是否能继续 |
| 任务与入口 | 稳定编号、独立对话、总览、Project 与分组区别 | 客户端实际可用工具需由用户自己的 Codex 检查；创建入口需明确请求 |
| 执行与回传 | 一个下一步、本人结果与 AI 产物分开、短状态回传 | 仍需任务对话或本人更新；真实结果不能由活动信号替代 |
| 长对话续接 | 短交接、历史索引、来源版本与恢复提示词 | 现有任务已做一次记录纠偏；全新对话及不同用户独立续接尚待验证 |
| 查看任务进度 | 本地原型共享清单可显式更新和展示；公开提供手动协议 | 增量检查器未交付；不一致时按需核对，token 与长期效果未测量 |
| 小屋子软件 | 相关实现仍在依赖链草稿 PR 与本地修改中 | 完整发布、任务跳转、退出重开和另一台设备安装仍需验收 |
| 分发与更新 | main 提供通用指南、模板和 bootstrap；个人资料留在本机 | 使用者必须拉取新版本并读取变化，不会自动更新已经打开的全部对话 |
| 阶段完成与退出 | 完成条件、历史保留、暂停与当前入口约定 | 持续试用检查：任务真完成时是否收尾，卡住时是否找到更小一步 |

## 首次可用的验收

使用者应能在自己的 Codex 中完成：读指南 → 说出自己的事情 → 校正短清单 → 选择任务入口 → 做一个行动 → 回传实际结果 → 下一次找到正确的下一步。记录初次需要多少解释、哪里误解，不只记录页面能打开。 独立首次使用与续接验收在 [Issue #76](https://github.com/johnnyzhang-eng/career-workbench/issues/76) 跟踪，尚未完成。仓库的离线测试验证旧 CLI 底座，不验证这套访谈的效果。

## 当前 PR 合并范围

本次合并产品与协作基线 #7，以及任务方法与续接文档 #75。两者提供设计边界和可复制使用流程。其余草稿包括岗位发现、学习计划、原生小屋子与艺术实验；按依赖逐段核对行为、隐私与安装条件后交付，不为了减少 PR 数量把实验全部放进 main。

小屋子与清单代码交付时，还要给出完整安装入口和虚构工作区示例；不能要求新用户从多个试验 checkout 找出当前版本。未完成的实现继续在关联任务中维护；方法的使用者可以先用 Markdown。

## 持续更新

在新会话开始或主动更新方法时，按[入门页](start-here.md)中的更新流程检查 main，查看[演进记录](codex-task-project-evolution.md)，保存本机已采用的提交。改变回传字段、入口或状态含义时，提供迁移说明；新版本不能替使用者重排私人任务。用户的反馈先留通用卡点与虚构复现，不公开原始私人记录。
