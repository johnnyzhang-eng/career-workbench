视频里屏幕上的长提示词和完整分支条件受分辨率限制，不能可靠逐字抄写；这里仅记录可辨认的意图和操作顺序。视频画面、作者对白与我们自己的产品决定分开保存，不把视频截图提交到公开仓。

## 一个真实用户日：先做工作流，再让房间表达它

```mermaid
flowchart LR
  A[01 选择秋招或 CET6 目标] --> B[02 看有来源的七日建议]
  B --> C[03 本人确认并同步今日清单]
  C --> D[04 选择任务并开始行动]
  D --> E[05 小窗显示可辨认的动作]
  E --> F[06 记录练习或求职证据]
  F --> G[07 本人确认结果与复盘]
  G --> H[08 明日建议及有限自动调整]
```

- **房间是当前活动的表达**：计划任务只给「下一步建议」，人物保持待机；本人点开始或明确连接的工具事件才进入桌前、读书、面试准备等动作。暂停、结束只改活动状态，不打勾。
- **清单是真实工作台**：任务显示来源、完成条件、时间与证据入口。完成练习、投递或考试结果使用各自的证据规则；场景动画不能反推结果。
- **时间与现实同步**：日期、时刻和昼夜取目标时区的本地时钟。跨日与电脑休眠后重新计算视图；错过任务给温和反馈，不扣分。真实岗位或考试日期不会因为时钟走动就自动变成已核验。
- **调整有边界**：系统可自动排序、挪动尚未开始的弹性时段，保留记录并可撤销；变更目标、截止日、完成条件或已开始任务须本人确认。

## 三层窗口与信息密度

| 层级 | 默认呈现 | 操作 | 验收问题 |
|---|---|---|---|
| 收起 | 房子/角色状态提示 | 点开小窗 | 角落图标能否明确表示有任务，同时不打断当前电脑工作？ |
| 角落小窗 | 房间、人物、时间、最靠前的行动、开始/暂停 | 展开工作台或收起 | 约 320–360px 宽时能否看懂「电脑前」「读书」「面试准备」的区别？ |
| 展开 | 左侧场景，右侧目标、今日清单、来源和证据入口 | 切目标、复盘、接受计划 | 场景与清单是否指向同一任务；实际结果是否有可追溯来源？ |

网页样机可以验证布局与数据流，但操作系统层的置顶、透明、鼠标穿透、唤醒与退出须在桌面容器中单独试验。窗口默认不应覆盖用户正在输入的区域；透明或简化只改变显示，不改变任务状态。

## 美术探索与质量门槛

现有 3D 样机的光影是用户认可的质量参照；此前所谓改良版偏粗糙。此前生成的「像素」图是缩小插画，用户已明确指出它不是真像素。不要把插画降采样再称像素。首轮原创 320×180 正交像素房间和多动作人物仅用于跑通视觉插槽，质量尚待实机比较。

1. **同一任务、同一尺寸对照**：电脑前工作、读书、面试准备各取一个真实清单任务；在 320px 小窗和展开视图中并列看原 3D 光影、原生 2D 像素、2.5D 插画。比较人物轮廓、动作、道具、氛围、文字可读性和遮挡，不凭大图偏好定路线。
2. **原生像素规范**：先确定画布尺寸、网格、视角、调色板、角色脚底基线与最近邻缩放；各姿态需对应动作，不靠一张静态角色变换文字。视频中的 3D 透视可作为单独候选，不能伪装为 2D 像素。
3. **素材与许可**：优先实机试 [2dPig Pixel Office](https://2dpig.itch.io/pixel-office) 的 CC0 俯视办公室角色/家具，另对照 [Syntaxes of Play 16×16 Interior](https://synofplay.itch.io/retro-interior-expansion-pack-1616) 与 [OpenGameArt 16×16 Base Sprites](https://opengameart.org/content/16x16-base-sprites)。下载前再次核对原页许可、文件内许可与角色/家具透视是否一致；入公开仓时记录来源、作者、许可证和修改范围。候选素材尚未接入当前画面。
4. **照片生成角色**：提供本人主动选择照片的本机私有入口、预览和删除；取得本人认可后，才选用合适生成服务或本机流程，明确成本和图片使用范围。输出要能复用同一角色的多个动作和透明背景，并在小窗验收脸/发型/衣着的可识别性。没有照片时使用通用角色，不预填个人形象。

## 实施顺序与可验收交付

| 阶段 | 实现与证据 | 过关条件 |
|---|---|---|
| S1 目标链 | 秋招/CET6 目标、模板提案、本人接受、同步每日清单 | 重启后事实与状态恢复；没有确认就不写入执行计划。 |
| S2 场景链 | 今日任务选择、开始/暂停/继续/结束、独立动作存储、昼夜同步 | 房间与任务同源；计划不装作正在做；动作不装作已完成。 |
| S3 三层 UI | 收起、角落、展开；同一目标和清单；场景组件可换 renderer | 三层能互相往返，缩小时无遮挡和错误点击。 |
| S4 真实证据 | CET6 首次作答/错因、秋招岗位核验/投递回执、结果复盘桥 | 每类结果保留来源，模拟反馈与真实事件分离。 |
| S5 美术决策 | 2D 原生像素与原 3D 同尺寸、同动作实机对照，照片角色路径 | 由用户看运行画面定优先风格；不能以一张生成图代替多状态测试。 |
| S6 桌面容器 | 置顶/透明/穿透/唤醒/退出与睡眠跨日实测 | 不抢焦点、不妨碍日常工作；状态在收起和重启后保持一致。 |

本文件是可审查的设计与验收依据，不声称 S4–S6 已实现。每轮 UI 评审记录具体截图、窗口尺寸、所处任务和待改问题，再决定下一次美术投入。
