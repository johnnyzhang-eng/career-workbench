# MVP 规格 v0.3（资源导航优先，待实现）

已有：本地 CLI/SQLite 求职状态机。拟建：岗位要求到外部课程的可解释导航、学习进度和待验证证据。待验证：资源选择效果、初学者启动门槛和跨用户价值。

## 首条用户路径

N1 选择一个或多个目标岗位 → N2 核对要求与技能映射 → N3 查看推荐的外部具体章节及理由 → N4 去原站学习 → N5 返回记录进度与证据引用。

原始岗位入口全程可打开，学习不是人工投递前置门槛。首片使用虚构岗位、人工确认映射和少量手工资源元数据；模型明确未配置，规则推荐不冒充 AI 缺口分析。

## 外部资源是学习主路径

工作台组织已有课程、书籍、官方文档和题库；不建设自有 SQL 第一课、完整课程或站内判题系统。资源卡必须落到具体章节，包含语言、形式、前置、难度/目标、访问条件、核验状态、匹配理由和替代项。只保存必要元数据与原始链接，不复制或嵌入第三方内容。

零基础用户得到合适的外部入门章节；前置不满足或资源不匹配时显示原因并允许替换。单次网络异常不证明资源永久失效，检查时可访问也不证明适合所有学生。

首批 SQL 只是验证资源匹配契约的样本，后续 Python、算法等沿用该契约，不靠自制课程数量扩展产品。

## 进度与能力证据

点击只记 opened，用户可记录 in_progress 或 completed_self_reported。保留事件及可选的本地证据引用；刷新和重启能找回。首片证据状态保持 unverified，不因看完、打卡或提供链接自动变成独立掌握。

能力验证后续独立设计，可研究外部练习结果、独立作品或复测证据。尚未决定验证实现方式，不先做题库、判题器或 48 小时复测引擎。

## 岗位与模型边界

后续岗位入口支持用户链接/JD、人工样本和许可明确的公开接口。提取字段先待核对；保留原始岗位页、投递页、具体来源和核验时间。网页错误、HTTP 200 或接口仍有记录都不能替用户确认开放状态与资格。

用户自带模型只提出可撤销、带来源的候选映射/建议。调用前预览最少必要数据和费用，取得授权；密钥不进前端、仓库或日志。没有模型时仍可手动选择资源和记录进度，个性化分析标未分析。后端保持单体，外部调用与领域规则分离。

## 首片验收

两份虚构 JD 共通 SQL 要求指向同一技能，另一份的流处理要求独立保留。学生能从原文解释为什么推荐某个章节，根据语言与前置替换资源，打开原站并返回记录进度。自报完成后能力仍待验证，原岗位入口不受学习状态影响。

验证无模型、无匹配、资源待重验、未知资格、重复提交、存储异常与重启恢复。网页只监听本机，不暴露 private/，不读取外部学习账号，不复制第三方正文，不产生收费调用。

完整 Alpha 后续再加入真实岗位、用户纠错与经授权的模型建议；首片不等于完整 Alpha，也不等于能力改善已经证实。
