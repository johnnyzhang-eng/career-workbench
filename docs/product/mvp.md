# MVP 规格 v0.2（本地对齐草案）

状态词：**已有**=当前仓库有相应命令行能力；**拟建**=尚无可验收产品行为；**待验证**=有方案但用户价值或数据源未获证实。它们不等同于“上线”。

## 端到端主流程

```text
N1  选择一个或多个目标方向            拟建：可解释、可调整，不输出录用概率
 ↓
N2  汇集具体岗位及原始投递入口        已有：手动保存 URL；供给、核验与可点击界面拟建
 ↓
N3  按方向对照 JD 与个人证据          拟建：共通/专属缺口、来源与未知项可见
 ├── N4A 现在可投 → 本人到原站提交 → 带回回执   已有人工记录底座；网页入口拟建
 └── N4B 暂缺能力 → 原创小题/实作 → 现成资源   拟建：按缺口组织，不自建全套课程
                         ↓
             N5 记录首次尝试、提示与结果        已有证据记录底座；判题拟建
                         ↓
             N6 间隔后用新题复测                拟建；真实验收待做
                         ↓
N7  更新各目标方向的证据和下一步      拟建；投递反馈也可触发重估
```

N4A 与 N4B 并行，学习不是投递前置门槛。任一步证据不足都允许停留在“未知/待确认”；不能替用户填写“符合”“已掌握”或“已投递”。

## 岗位入口：混合来源方案（拟建、待验证）

首版不把岗位来源押在单一渠道上：学生可粘贴具体岗位链接或 JD 正文，也可导入自己用 AI 辅助搜索后找到的链接；工作台提供少量经人工核验的岗位样本，并研究按企业读取公开招聘系统的职位接口。用户使用外部 AI 找到的结果仍只是线索，必须保留具体来源 URL 和核验日期。第三方聚合 API 只有在目标地域与实习岗位覆盖、展示/署名条款及持续使用权通过核验后才接入；不以“有免费额度”替代这些检查。

对一个岗位链接，按以下顺序尝试读取：已支持的官方招聘系统接口 → 页面公开的 `JobPosting` 结构化数据 → 可正常访问的职位正文。读取失败、需要登录或页面仅由浏览器动态渲染时，保留链接，允许学生粘贴 JD 正文；不绕过反爬、验证码或账号限制。只保存对完成任务必要的字段与来源，不在公开仓库转载第三方 JD 全文。

提取出的公司、确切职位、城市、实习/校招类型、届别、学历、截止、职责和技能先作为**待核对草稿**。每项要能回到原文片段或链接；缺失写“未知”，不能由模型补猜。原始岗位页与投递入口可能不同，分别保存并在打开前重验。HTTP 成功、接口仍有记录或 AI 声称“在招”都不足以确认用户可投；本人最终核对开放状态与资格。

第一轮验收用真实目标方向中的少量岗位做对照：记录每个来源能否给出确切职位页、有效投递入口、完整 JD、地域和届别，统计人工补录与误判。若接口来源覆盖不到目标用户，不增加抓取强度，而回到人工核验样本与用户导入；保留来源适配器的可插拔边界。

## LLM 辅助补差：用户自带模型（拟建、待验证）

模型层要可替换，而不是把某家服务写死在产品逻辑里。学生可选择自己有权使用的模型服务；本地模型与不同 API 供应商作为适配方向，首版只承诺实际完成并验收过的接入方式。若用户只有聊天工具而没有可调用接口，可先提供“导出必要上下文 → 用户自行询问 → 导入结果”的受限路径；这仍要经过同一套来源和证据复核，不能假装是自动分析。任何按次付费的调用都需先显示预计范围并经用户确认。

LLM 的任务是理解和提出**候选判断**：从 JD 抽取技能与门槛，将项目经历、练习作答和面试反馈映射到要求，区分共通/方向专属缺口，建议下一道练习、资源和提示层级。每条判断至少包含对应的 JD 片段、个人证据位置、判断理由和“已证实/待验证/未知”状态；缺来源就保留未知。用户可以修正或撤销。模型不得仅凭自述、简历关键词或自己生成的答案判“独立掌握”，也不得给出录用概率。

模型不负责偷偷抓取受限网页或替学生投递。发送前预览要传给模型的内容；默认不发送完整简历、音频、联系人和投递回执。凭证只保存在用户控制的私有环境，不能进入公开仓库、分享链接、日志或示例。没有模型时，岗位链接、外部资源、手动记录与可机械判分的练习仍可使用，但个性化缺口应明确标注“未分析”。

## 练习与资源：工作台拥有连接，不拥有全套课程

资源目录只收录元数据：稳定 ID、对应能力与前置知识、标题、合法链接、语言、版次/章节、访问条件和最近核验日期。资源可为书、开放教程、官方文档或现成题库；只引用，不复制课程、付费正文或第三方题目。

本产品只做少量原创诊断题、实作任务与复测变式。每个练习单元至少有：对应的一个或多个岗位要求、题型和前置、题目与可观察正确性检查、分层提示、记录求助程度的方式、失败后推荐的外部资源、复测变式。SQL/Python 可用实际运行结果，概念、建模与数据严谨性题需要明确评分依据；不能用选择题分数直接代表工作能力。

通用引擎负责排今天任务、保存首次尝试和求助方式、提醒复测、把新证据回流到各目标方向。完全零基础者先得到最短必要解释或零前置外部资源，而不是被中等面试题拦住。可选的助手 skill 只规定提示行为（先让学生尝试、分层提示、不替写、检查答案）；不把课程内容、私密记录或“已掌握”结论写进 skill 指令。无助手时，用户仍应能看资源、做题和记录结果。

## 初始能力地图：测评主题优先级假设

| 层级 | 内容与可观察验收 | 进入条件 |
|---|---|---|
| 基础重建 | SQL：从表/行/列、筛选到聚合、连接、分组 Top N；Python：阅读执行顺序、数据结构、函数、测试；算法：复杂度、数组/哈希/基础遍历 | 首批真实用户已显示独立基础不足；不能直接从中等面试题开始 |
| 数据工作通用 | 数据粒度/主键/分层与建模、口径与分母、空值/重复/抽样/金标、可追溯测试 | 由目标 JD 与项目追问触发；要求能解释自己的数据决策 |
| 岗位分支 | 数据工程：Spark 分区/shuffle、Kafka 消费与重放、ClickHouse 表引擎和增量链路；研发：更深算法、代码设计与测试；AI 数据/评测：指标、抽样、标注质量、误差分析 | 只在岗位要求或面试证据出现时加深，不要求所有人学全栈 |
| 条件性扩展 | Redis、TypeScript、Flink、云平台等 | 有具体岗位或项目任务才进入“今天”；不能为凑技能列表而排课 |

这是候选测评主题，不是完整课程清单，也不表示题目已经制作。首条端到端验证先选两个都要求 SQL 基础的目标岗位；Python、算法等领域只在同一“岗位要求—练习证据”结构经验证后扩展。

## 首条 SQL 验收场景

给初学者一份虚构订单表和两类虚构岗位的基础要求。首个原创诊断题只检查是否理解表/行/列及 `SELECT`/`FROM`；做不出时给一个简短概念提示和可打开的零基础外部资源，不在本站展开完整 SQL 课程。`WHERE`、聚合、连接和每组取前三留给后续题型。学生可以要求提示，但提示后的同题答案不得记为“独立通过”；需换一道新题独立完成。在间隔后用新数据和同类变式题复测；保存题目、答案、执行结果、求助程度与解释。只靠“已读章节”或“AI 给出答案”不能过关。

同时，系统保留原岗位链接及核验时间；链接无法打开或资格未核实时，显示待确认而不把岗位标为可投。投递仍由本人完成，只有本人记录的真实回执才能进入 submitted。

验收重点是行为与证据，而非页面存在：新手无需先打开 VS Code 就能完成第一道小题；失败后能找到合适的现成资源；复测结果按对应岗位要求更新“证据/未知”而非录用概率；私人数据不进入共享仓库或未经同意的外部模型调用。
