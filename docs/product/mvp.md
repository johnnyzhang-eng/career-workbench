# MVP 规格 v0.5（本地 agent 岗位发现与原站投递优先，待验收）

主线已有：本地 CLI/SQLite 求职状态机。开发中：每人本地 agent 的岗位候选交接与原站投递入口（#9），再接岗位要求到外部课程的可解释导航、学习进度和待验证证据（#8）。待验证：agent 候选质量、招聘来源覆盖与维护成本、初学者启动门槛、资源选择效果和跨用户价值。

## 第一切片：发现岗位并去原站投递（#9）

J1 每位学生用自己的本地 agent 按个人条件持续找岗 → J2 agent 按受控契约将候选、原始职位页、来源时间、推荐理由和未知项交给本人工作台 → J3 本地去重并按城市、方向、届别等筛选 → J4 本人核对原站 JD、资格和是否开放 → J5 打开原职位或独立投递入口 → J6 本人在原站投递，按真实回执返回登记。可选的公开招聘来源刷新为工作台补充候选，不替代本地 agent。

共享的是 agent 交接格式、来源适配器和本地网页；每人单独保存偏好、收藏与投递记录，不把多个用户的私有数据集中到公开服务。agent 可由本人选择，工作台不自动启动付费模型或任意网站抓取；首次通过网页粘贴或当前私有工作区的文件接收结构化 JSON，导入错误不能覆盖已有候选。单次手工贴岗位可补充，但不冒充持续发现；agent 的持续运行和候选质量仍需真实用户验收。来源身份、时间、引用及重复导入要可追溯，公开接口刷新失败时保留最近成功快照。职位链接与独立 apply 链接分开；来源无独立 apply 链接时引导用户在原站查看。点击链接不等于已投递，agent 推荐与接口响应都不能自动确认资格或开放状态。学习不是投递前置门槛。

第一切片用两个虚构用户、两组虚构 agent 输出、离线职位响应和一个人工核查的公开来源样本验收。不做需登录的网站抓取、绕验证码、自动海投、多用户云账号或全网搜索。来源列表、agent 输出来源、接口异常和维护范围要明确告诉用户。

## 第二切片：外部课程导航（#8）

N1 选择已有具体岗位 → N2 核对要求与技能映射 → N3 查看推荐的外部具体章节及理由 → N4 去原站学习 → N5 返回记录进度与证据引用。

这一阶段使用虚构岗位、人工确认映射和少量手工资源元数据；模型明确未配置，规则推荐不冒充 AI 缺口分析。

## 外部资源是学习主路径

工作台组织已有课程、书籍、官方文档和题库；不建设自有 SQL 第一课、完整课程或站内判题系统。资源卡必须落到具体章节，包含语言、形式、前置、难度/目标、访问条件、核验状态、匹配理由和替代项。只保存必要元数据与原始链接，不复制或嵌入第三方内容。

零基础用户得到合适的外部入门章节；前置不满足或资源不匹配时显示原因并允许替换。单次网络异常不证明资源永久失效，检查时可访问也不证明适合所有学生。

首批 SQL 只是第二切片验证资源匹配契约的样本，后续 Python、算法等沿用该契约，不靠自制课程数量扩展产品。

## 进度与能力证据

进入第二切片后，课程点击只记 opened，用户可记录 in_progress 或 completed_self_reported。保留事件及可选的本地证据引用；刷新和重启能找回。证据状态保持 unverified，不因看完、打卡或提供链接自动变成独立掌握。

能力验证后续独立设计，可研究外部练习结果、独立作品或复测证据。尚未决定验证实现方式，不先做题库、判题器或 48 小时复测引擎。

## 岗位与模型边界

第一切片岗位入口以本地 agent 候选导入为主，支持有文档的公开接口补充和人工粘贴。提取字段先待核对；保留原始岗位页、投递页、具体来源、发现时间与核验时间的区别。网页错误、HTTP 200、agent 理由或接口仍有记录都不能替用户确认开放状态与资格。

用户自带模型只提出可撤销、带来源的候选映射/建议。调用前预览最少必要数据和费用，取得授权；密钥不进前端、仓库或日志。没有模型时仍可手动选择资源和记录进度，个性化分析标未分析。后端保持单体，外部调用与领域规则分离。

## 第一切片验收（#9）

两名虚构用户在各自私有工作区导入不同 agent 输出，按不同条件得到不同职位列表，彼此记录不串用。重复导入无重复候选、错误输入不覆盖旧内容；来源和推荐依据可追溯，资格与开放状态保持待核验。可选公开来源重复刷新无重复职位，网络故障保留最近成功快照。用户能看到原始链接、来源时间和未知字段，打开原站职位页和可用的投递入口；操作不自动产生 submitted。只有本人实际完成申请且有真实回执才按旧状态机登记。持续发现与候选可投比例仍需真实使用核查。

验证 agent JSON 格式错误、跨工作区路径、重复候选、伪造来源、恶意 URL/JD，以及公开来源返回空列表、失败或职位暂时消失、未知资格、存储异常与重启恢复。网页只监听本机，不暴露 private/，不读取外部账号，不复制第三方正文，不产生收费调用。

## 第二切片验收（#8）

两份虚构 JD 共通 SQL 要求指向同一技能，另一份的流处理要求独立保留。学生能从原文解释为什么推荐某个章节，根据语言与前置替换资源，打开原站并返回记录进度。自报完成后能力仍待验证，原岗位入口不受学习状态影响；无模型、无匹配和资源待重验状态仍须诚实显示。

完整 Alpha 后续再做可供其他学生独立安装与运行的 agent 交接说明、更多已核查来源、真实用户反馈与经授权的模型建议；第一切片不等于完整 Alpha，也不等于职位来源覆盖或求职成效已经证实。
