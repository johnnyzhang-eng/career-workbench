# MVP 规格 v0.1

状态词：**已有**=当前仓库有相应命令行能力；**拟建**=尚无可验收产品行为；**待验证**=有方案但用户价值或数据源未获证实。它们不等同于“上线”。

## 端到端主流程

```text
N1  选目标岗位并保存原始链接/JD      已有：人工录入；自动发现待验证
 ↓
N2  核对资格、时效和岗位要求          已有：核验门槛；要求抽取拟建
 ↓
N3  对照履历、练习与面试反馈，排缺口  拟建：来源与信心必须可见
 ↓
N4  选一门学习包及具体资源章节        拟建：SQL / Python / 算法等共用格式
 ↓
N5  生成今天的小任务                  已有通用待办；学习内容编排拟建
 ↓
N6  本人尝试、标注求助程度、获得反馈  已有练习证据记录；教学/判题拟建
 ↓
N7  隔天用变式题复测                  拟建；真实验收待做
 ↓
N8  更新证据，重看岗位与投递记录      已有人工记录；自动重算拟建
```

任一步证据不足都允许停留在“未知/待确认”；不能替用户填写“符合”“已掌握”或“已投递”。

## 学习包：可扩展内容，不是 Codex skill 文件

每个学习包至少有：稳定 ID/版本、主题与前置知识、面向的岗位能力、零前置入口、资源元数据（标题、合法链接、语言、版次/章节、可访问性和最近核验日期）、每天可完成的知识单元、示例与练习、正确性检查、常见错误、完成证据、复测变式。资源可为书、开放教程、官方文档或本地教材；只引用，不复制付费正文。

通用引擎负责排今天任务、保存首次尝试和求助方式、提醒复测、把新证据回流到岗位缺口。可选的助手 skill 只规定教学行为（先让学生尝试、分层提示、不替写、检查答案）；不把课程内容、用户私密记录或“已掌握”结论写进 skill 指令。无助手时，用户仍应能看资源、做题和记录结果。

## 初始能力地图：内容优先级假设

| 层级 | 内容与可观察验收 | 进入条件 |
|---|---|---|
| 基础重建 | SQL：从表/行/列、筛选到聚合、连接、分组 Top N；Python：阅读执行顺序、数据结构、函数、测试；算法：复杂度、数组/哈希/基础遍历 | 首批真实用户已显示独立基础不足；不能直接从中等面试题开始 |
| 数据工作通用 | 数据粒度/主键/分层与建模、口径与分母、空值/重复/抽样/金标、可追溯测试 | 由目标 JD 与项目追问触发；要求能解释自己的数据决策 |
| 岗位分支 | 数据工程：Spark 分区/shuffle、Kafka 消费与重放、ClickHouse 表引擎和增量链路；研发：更深算法、代码设计与测试；AI 数据/评测：指标、抽样、标注质量、误差分析 | 只在岗位要求或面试证据出现时加深，不要求所有人学全栈 |
| 条件性扩展 | Redis、TypeScript、Flink、云平台等 | 有具体岗位或项目任务才进入“今天”；不能为凑技能列表而排课 |

这是内容地图，不是宣称每一门课程都已制作。首条端到端内容验证选 SQL 基础，同时用 Python 和算法各做一个最小单元，检验学习包格式能否扩展。

## 首条 SQL 验收场景

给初学者一份虚构订单表和来自虚构岗位的要求。系统从“表、行、列、`SELECT`/`FROM`/`WHERE`”开始，逐步到按渠道与用户汇总、每组取前三；每步提供明确资源位置、一道练习和提交方式。学生可以要求提示，但提示过的尝试不得自动记为“独立通过”。在 48 小时后用新数据和同类变式题复测；保存题目、答案、执行结果、求助程度与解释。只靠“已读章节”或“AI 给出答案”不能过关。

同时，系统保留原岗位链接及核验时间；链接无法打开或资格未核实时，显示待确认而不把岗位标为可投。投递仍由本人完成，只有本人记录的真实回执才能进入 submitted。

验收重点是行为与证据，而非页面存在：新手无需先打开 VS Code 就能完成首课；课程不会从窗口函数起跳；训练结果确实改变技能状态；私人数据不进入共享仓库或外部模型调用。
