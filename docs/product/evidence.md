# 证据与研究计划 v0.2（本地对齐草案）

状态：以下为匿名化的早期观察与待验证假设；仓库不保存个人材料原文、画像或逐字稿。

## 已观察到什么

| 观察 | 证据边界 | 对产品的含义 |
|---|---|---|
| 早期个体反馈显示：有 AI 协助完成的项目经验，不一定意味着能独立完成同类基础题 | 单人自述；原始材料不在本仓库，不代表总体 | 项目事实与独立能力要分开建模；诊断须有“不会/尚未尝试”状态 |
| 早期个体反馈显示：技术面试会围绕简历技能追问，也可能要求现场解题 | 单人反馈；具体题目、环境与评分口径尚待本人复核，不公开原话或材料 | 从真实追问反推练习；完成标准是独立作答与解释，不是读完资源 |
| 当前命令行原型能记录人工投递；目标选择、资源聚合和复测闭环尚未作为产品验收 | 本仓库代码与测试，不是第三方用户成功验证 | 产品发现接在已有投递记录能力上，不重复开发一个看板 |
| PathFinder 提供职业偏好匹配、手动 JD 分析和 SkillForge 模块；其零基础 SQL 教学与真实职位发现是否覆盖本产品所需闭环，仍未完成端到端核验 | 2026-09-16 审阅[上游仓库](https://github.com/mojaffri/PathFinder)的本地源码；未完成登录后真实用户端到端验收 | 可借鉴模块结构；是否贡献 PR 或独立开发仍待选择 |
| 课程、题库及“测评→推荐学习→复测”已有产品提供 | 2026-09-17 核对 [SQLBolt](https://sqlbolt.com/)、[StrataScratch](https://www.stratascratch.com/)、[DataCamp Signal](https://www.datacamp.com/signal) 与 [roadmap.sh](https://roadmap.sh/premium) 的官方说明；尚未用同一学生任务实测各产品 | 不把聚合或测验本身宣称为壁垒；先检验具体 JD、个人证据、练习和投递反馈能否形成更有用的连接 |
| 部分招聘系统提供按企业读取公开职位的接口，并返回原站岗位或申请链接 | 2026-09-17 核对 [Greenhouse Job Board API](https://docs.greenhouse.io/job-board.html)、[Lever Postings API](https://github.com/lever/postings-api) 与 [Ashby Job Postings API](https://developers.ashbyhq.com/docs/public-job-posting-api) 官方文档；尚未实测中国实习岗位覆盖和长期使用条款 | 可做可插拔岗位来源，不等于已有跨公司岗位搜索，也不等于接口返回的岗位仍可投 |
| 聚合职位 API 也可能带明显使用限制 | [Adzuna API 条款](https://developer.adzuna.com/docs/terms_of_service)有额度、展示署名和持续使用限制；[Remotive Public API](https://remotive.com/remote-jobs/api)要求回链署名并延迟公开岗位 | “免费”不是无条件；接入前须核对许可、地域与岗位类型 |

上述私有观察只允许抽象为通用问题。公开文档不得包含可识别的公司、职位日期、原话、项目数字、联系人或链接参数。转写与录音不能自动成为“真实答题失败”的定论；先与当事人核对题目、环境与评分口径。

## 尚待验证的假设

| 假设 | 最小验证 | 反证信号 |
|---|---|---|
| H1：允许保留多个目标方向，并区分共通/专属缺口，比强迫学生先选唯一岗位更有助于行动 | 让学生比较两类真实岗位，选择当周的一项共通练习与一项方向专属待办 | 比较后仍不知道为什么先做哪一项，或多目标只增加负担 |
| H2：记录求助程度与延迟复测比“读完/打卡”更能反映独立能力 | 对同一知识点安排首次尝试和 48 小时后变式题 | 有打卡但独立复测持续失败，或系统无法解释结果 |
| H3：聚合现成课程/书籍/题库比自建完整课程更适合作为起点 | 测验后给出可访问、前置匹配的资源位置与下一道原创小题，观察能否继续 | 链接不可用、版本不符、资源难度不匹配，或阅读后仍不知道下一步 |
| H4：一套“岗位要求—练习—资源—复测”结构能覆盖 SQL、Python 和算法 | 用三个不同题型各配置最小单元，不改调度与证据数据结构 | 每添一门主题就必须重写核心引擎，或统一结构抹掉题型差异 |
| H5：职位链接必须带来源和核验时间 | 用户用保存的链接尝试回到官方职位 | 链接失效、跳到岗位列表或资格信息发生变化仍未提示 |
| H6：把目标岗位、测验结果与资源放在一起，比直接使用现有学习平台更有帮助 | 同一学生分别完成“现有资源自行组合”和“工作台引导”的真实任务，比较目标解释、下一步选择与复测结果 | 工作台没有减少迷茫或行动成本，只是多一层网址目录 |
| H7：用户自带模型能在不替代能力验证的前提下，提出更有用的缺口与练习建议 | 同一批岗位与作答由模型提出有来源的缺口草稿，再由学生核对和独立复测；记录错误、未知、费用与隐私理解 | 模型无依据地补猜技能、学生无法纠错、误把模型辅助结果当独立掌握，或接入成本阻断零基础用户 |

## 研究节奏与保护

发现阶段先做少量有同意的观察式访谈，覆盖 P0 和 P1，不只问“你喜欢什么功能”：请参与者比较两类真实岗位、说明为何选择其中一个或两个、解释一道相关追问并尝试一个小练习，再打开推荐资源和岗位原始链接。记录任务是否完成、在哪里卡住、是否求助，而不是只记录满意度。第一轮以 4–8 人作为定性研究范围的参考，不据此推算市场比例；之后按发现迭代。[GOV.UK 用户需求研究](https://www.gov.uk/service-manual/user-research/start-by-learning-user-needs)建议先观察真实需求，并把未来自用户的意见视为待证假设；[其研究计划指南](https://www.gov.uk/service-manual/user-research/plan-user-research-for-your-service)强调把发现反馈进优先级和待办。

参与者的简历、面试音频、作答和岗位申请默认只在本人本地；研究须事先说明用途、保存期限与退出方式。对外只写不可逆识别的汇总结论和虚构演示，不把“一名用户的面试经历”包装成市场调查。
