# 证据与研究计划 v0.1

状态：以下为匿名化的早期观察与待验证假设；仓库不保存个人材料原文、画像或逐字稿。

## 已观察到什么

| 观察 | 证据边界 | 对产品的含义 |
|---|---|---|
| 一位真实使用者有 AI 辅助完成的项目，也确认独立 Python / SQL 基础不稳 | 本地简历、自述和面试转写；单人、转写可能有误，不代表总体 | 项目事实与独立能力要分开建模；诊断须有“不会/尚未尝试”状态 |
| 一次技术面试中，岗位方根据简历追问数据库、分布式计算和 SQL，并要求现场完成分组排序题 | 私有转写需由本人复核；不能在共享仓库复制录音或原话 | 从真实追问反推练习；完成标准是独立作答与解释，不是读完资源 |
| 当前命令行原型能记录人工投递；教学与复测闭环尚未作为产品验收 | 本仓库代码与测试，不是第三方用户成功验证 | 产品发现接在已有投递记录能力上，不重复开发一个看板 |
| PathFinder 提供职业偏好匹配、手动 JD 分析和 SkillForge 模块；其零基础 SQL 教学与真实职位发现是否覆盖本产品所需闭环，仍未完成端到端核验 | 2026-09-16 审阅[上游仓库](https://github.com/mojaffri/PathFinder)的本地源码；未完成登录后真实用户端到端验收 | 可借鉴模块结构；是否贡献 PR 或独立开发仍待选择 |

上述私有观察只允许抽象为通用问题。公开文档不得包含可识别的公司、职位日期、原话、项目数字、联系人或链接参数。转写与录音不能自动成为“真实答题失败”的定论；先与当事人核对题目、环境与评分口径。

## 尚待验证的假设

| 假设 | 最小验证 | 反证信号 |
|---|---|---|
| H1：岗位驱动的短任务比泛用课程更容易启动 | 观察不同基础的学生从一条 JD 进入首个 20–30 分钟任务 | 用户看不懂为什么这条任务与岗位相关，或根本无法开始 |
| H2：记录求助程度与延迟复测比“读完/打卡”更能反映独立能力 | 对同一知识点安排首次尝试和 48 小时后变式题 | 有打卡但独立复测持续失败，或系统无法解释结果 |
| H3：书籍的具体章节可作为资源入口，但不能替代练习和反馈 | 给出可访问的章节定位与对应题目，观察是否能完成 | 链接不可用、版本不符、阅读后仍不知道下一步 |
| H4：一套学习包格式能覆盖 SQL、Python 和算法 | 用三个不同主题各配置最小单元，不改调度与证据数据结构 | 每添一门课就必须重写核心引擎 |
| H5：职位链接必须带来源和核验时间 | 用户用保存的链接尝试回到官方职位 | 链接失效、跳到岗位列表或资格信息发生变化仍未提示 |

## 研究节奏与保护

发现阶段先做少量有同意的观察式访谈，覆盖 P0 和 P1，不只问“你喜欢什么功能”：请参与者实际找一条岗位、解释一道简历相关追问、尝试一个小练习。记录任务是否完成、在哪里卡住、是否求助，而不是只记录满意度。第一轮以 4–8 人作为定性研究范围的参考，不据此推算市场比例；之后按发现迭代。[GOV.UK 用户需求研究](https://www.gov.uk/service-manual/user-research/start-by-learning-user-needs)建议先观察真实需求，并把未来自用户的意见视为待证假设；[其研究计划指南](https://www.gov.uk/service-manual/user-research/plan-user-research-for-your-service)强调把发现反馈进优先级和待办。

参与者的简历、面试音频、作答和岗位申请默认只在本人本地；研究须事先说明用途、保存期限与退出方式。对外只写不可逆识别的汇总结论和虚构演示，不把“一名用户的面试经历”包装成市场调查。
