# 私密数据与共享边界

| 可以共享 | 只留本地 private/ |
|---|---|
| 流程、代码、测试、空模板、虚构例子 | 姓名、学校、联系方式、毕业和工作时间线 |
| 泛化的岗位核验规则 | 真实简历、投递记录、面试题上下文和评价 |
| 官方招聘主页的通用链接 | 招聘者联系人、邮件、内推码、预约链接 |
| 无个人信息的 bug 复现 | token、cookies、登录态、客户/雇主材料 |

每位使用者自己 clone，自己运行 init，自己维护 private/。不要把两个人的状态混在同一个数据库。

Private 只是访问权限，不等于匿名。仓库所有者用户名、邀请名单、提交作者、PR 和通知仍可能展示身份。协作者可能克隆或转发；不要把“以后删掉”当成脱敏。

## 发布前

1. 用全新目录、全新 Git 历史，不导入私人工作区历史。
2. 仅显式添加 README、规则、docs、templates、源码、scripts、tests；不使用无审查的 `git add .`。
3. 运行 `python3 scripts/check_privacy.py`；该工具只检查拟共享文件，输出规则名而不打印命中秘密。
4. 在本地设置 `CAREER_PRIVATE_TERMS`（用 `|` 分隔）添加本人姓名、学校、旧雇主和独特项目名，再检查。不要把该变量值提交到仓库。
5. 人工检查 `git diff --cached`、`git ls-files`、`git log --format=fuller`；还要看图片、链接参数、提交信息、作者邮箱和路径。
6. 确认推送目标是预期的公开仓库、认证账号与仓库所有者一致，并再次确认待推提交中没有私人资料。邀请协作者前核对账号和最小必要权限。

扫描器不是匿名保证：它不能理解所有上下文，识别不到所有商业机密，也不审查远端权限或 Git 历史。被 Git 忽略的文件若曾被提交，仍可能存在历史里。

## 避免旁路泄漏

不公开复盘原文，不把申请回执截图贴 Issue，不向 CI 上传 private/，不把真实 JD 的个性化跟踪链接当示例。模板采用 example.com 虚构 URL；不得误当真实招聘链接。

本地数据库未加密。设备权限、备份与磁盘加密由使用者管理。发送私人数据给任何云端模型或服务前，另行确认其范围与授权。
