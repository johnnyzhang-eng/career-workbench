# 桌宠小屋与秋招首日流程：集成核验

状态：2026-09-25 的草稿集成，基于 PR #60，移植 PR #61 的原生桌宠小屋。只使用被 Git 忽略的 `private/pet-first-day-qa` 虚构工作区，没有真实岗位、简历、投递或用户照片。

## 合流边界

移植时只有 `scripts/check_privacy.py` 产生冲突。解决后保留 #60 的六张首屏对照图白名单，并追加桌宠 PNG 的精确路径；这些 PNG 都按块类型和 CRC 校验。`CompanionWindow.swift`、构建脚本和小窗说明保留 #60 的关闭、目标恢复及工作台源，同时加入 #61 的 74×74 透明小屋、点击展开、减少动态效果和初始 WebView 延迟加载。目标、每日任务、证据与结果流程没有改动。

## 本机首日交互

本机服务运行在 `127.0.0.1:8842`。用真实 HTTP 命令创建「虚构秋招首日桌宠测试」，以本地当天为起点提出七日计划，明确接受并同步；当天任务是「确定岗位筛选条件」。测试 app bundle 是从同一 Swift 源编译的私有 QA 版本，只把默认入口 URL 换成 `8842/collapsed?goal_id=G-PETAUTUMN20260925CREATE`，以便 CUA 启动隔离样本；跟踪的 Swift 文件未改默认 URL。

| 操作 | 直接观察 |
|---|---|
| 启动 | 原生可访问性树有「展开今日房间：房间里有人在书桌前」及「关闭小房间」；截图显示透明小屋和人物。 |
| 点击小屋 | 首次页面载入后，URL 是同一秋招目标的 `/compact?goal_id=...`；360×480 点视图显示房间、当前「确定岗位筛选条件」及「开始行动」。 |
| 点击开始 | 页面显示房间「整理」、任务「行动中」和「暂停行动」；页面明确说明这不代表任务完成。 |
| 收起再展开 | 返回 74×74 小屋；再点击后恢复同一 `goal_id`、同一行动中任务和暂停入口。 |
| 点击暂停 | 房间回待机，任务显示「已暂停」与「继续行动」。HTTP 状态仍为同一目标，场景 `idle`、行动 `paused`。 |
| 点击 × | CUA 对原窗口的后续读取超时，原生进程仍存活；这支持窗口被隐藏，但本轮没有完成菜单栏恢复的实体点击。 |

74×74 点的 CUA 实机截图在 Retina 上为 148×148 物理像素：屋顶与两面墙构成的小屋轮廓、桌子和深色头发的人物都能分辨；表情、书本细节和具体任务动作无法在该尺寸可靠辨认。CUA 截图只在本次工具输出中内嵌显示，没有可引用的本地截图文件路径；仓库内的 [`pet-room-idle.png`](../../prototype/macos/Resources/pet-room-idle.png) 是生成素材原图，**不是实机截图**。该图是 3D 感静态插画，不是像素画，也不代表首版美术路线已选定；像素与精修 3D 仍须按 #20 的同尺寸动态对照。

测试时没有填写完成依据，也没有确认实际结果；本轮交互没有产生已投递或已完成声明。#60 对完整证据与结果流程的独立 HTTP/浏览器验证仍见 [首日集成记录](compact-first-day-integration.md)。

## 验收与剩余项

- 标准 `prototype/macos/build.sh`、`plutil -lint`、全套 Python 单测、隐私扫描和 diff 检查在本分支运行。QA 结束后重建标准 bundle，私有 URL 变体不会进入 Git。
- Codex 应用本身拒绝 CUA 控制；桌宠交互参考来自 [官方 Pets 文档](https://learn.chatgpt.com/docs/pets)。本轮没有实测 Codex 前台遮挡、拖动、菜单栏恢复、双屏、全屏或动效逐帧顺滑度。
- 收起图像为可替换的静态空闲预览，尚不反映「整理」等活动状态。完整原生加 WebKit 进程树的长期资源预算仍待测。
