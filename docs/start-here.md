# 从这里开始：把左边的对话变成任务入口

同学版目前只使用 Codex 的总览、侧边栏分组、独立任务对话和本地短记录。不安装或启动小屋子、网页服务、CLI 演示或后台监测。每个人填自己的事情；这里提供协作方法与模板。

## 给已经使用 Codex 的同学

可以把 main 的本页链接交给自己的 Codex，或复制下面的启动消息。允许读取仓库方法，不等于允许读取所有私人文件。

```text
请使用 https://github.com/johnnyzhang-eng/career-workbench 的 main 版本。
如果已有本地 checkout，先检查工作区和实际远端；没有则克隆到我指定的目录。
本次只用 Codex 侧边栏和任务对话，不启动仓库里的应用或演示。
读 AGENTS.md、docs/start-here.md、docs/task-intake-interview.md 和
docs/codex-context-management.md，只使用这里的通用方法。
先和我做渐进访谈，收集我自己的事情，每轮 1–3 个问题。
不要复制作者或其他人的任务，不扫描未指定的私有资料。
在本地 private/ 创建我的清单与短交接；先展示任务拆分让我校正。
我明确要求时再创建独立对话，保留稳定编号与可识别标题。
先核对当前会话能否实际建聊、改标题和整理侧边栏；缺工具就给我
可复制的标题和首条消息，标记“待我手动落实”，不要说已经设置好。
不要为缺少管理工具而生成接口 schema 或编写探针。创建返回 ID 后
只核对该 ID；搜索暂时找不到空对话不能触发重复创建或归档重建。
编号只按我的 private/ 清单解释，不能照搬仓库示例或别人的 T02。
我引用旧对话时先有界核对其目标和结果；读不到就标未知，不凭标题猜。
总览负责安排与交接，实际投递、学习或项目工作进入合适的任务对话。
今天先帮我开始一件事，留下实际结果与下一步。
```

请自行指定本地目录，私人资料保存在自己的 `private/`。无需安装额外 skill 或切换到草稿分支。小屋子继续由作者试验，当前不向同学交付；[交付状态](method-delivery-status.md)区分了这一范围。

## 可以直接转发给同学

这套方法让 Codex 左边的对话变成任务入口：一个总览，每个持续任务一个对话。先和 AI 聊清楚自己的全部事项，再选一件开始。只用 Codex，不用安装其他应用。把下面这段粘到自己的 Codex 即可：

```text
请使用 https://github.com/johnnyzhang-eng/career-workbench 的 main 方法，
先读 docs/start-here.md 和它引用的首次访谈、长对话续接规则。
只用 Codex 的侧边栏、总览和独立任务对话，不启动小屋子或其他程序。
先渐进访谈收集我自己的事情，每轮 1–3 个问题，允许以后补充。
查漏急事、长期项目、想读的书、兴趣、想学的主题、重复责任、对外承诺和等待项，确认期限与稳定时间。
我讲完眼前急事后，还要问一轮没有截止日期但想长期保留的方向；
不要因为我先选一件事，就把其他方向当作不存在。
展示任务拆分让我校正；确认后我授权你为持续任务创建独立对话、
命名并整理侧边栏。新对话先建入口，不同时启动所有任务。
已确认的方向先落实入口；未决定是否建聊的方向继续留清单，不要互相等待。
先检查这次对话实际可用的建聊、命名和侧边栏工具，并核对我的任务编号。
缺工具时给我逐项可复制的标题、首条消息及手动操作清单；我确认前标待落实。
创建请求返回 ID 或仍在准备时先记录并等待，不因搜索不到就再创建。
不要把提议的标题或分组说成已经创建，也不要套用别人的 T02 含义。
引用旧对话先核对内容和范围；无法读取时标待核对，不凭标题复用。
我选定重点后，由对应任务对话推进具体工作；总览只做必要准备与回传。
个人清单和短交接保存在本地 private/，只读取我指定的个人资料。
今天先帮我完成一件小事，有实际结果才记录进展和下一步。
```

当前没有启用“对话太长自动建聊、任务完成自动归档”。长对话先保存短交接，是否换新阶段对话由使用者决定；[续接规则](codex-context-management.md)说明了可用步骤和后续设计。

作者另在自己的实际使用中验证[可选对话检查器](codex-thread-watch.md)：增量读取明确登记的本机日志，仅保留观察元数据。它不属于首次启动要求，只有本人要求监测才启用；模型复核有额外消耗，自动建聊与归档仍未实现。

## 第一次：复制这一段

```text
我想用“一个总览 + 每个持续任务一个对话”组织事情。
先在当前对话和我聊清楚，不立即创建大量对话。
按 task-intake-interview.md 渐进访谈，每轮 1–3 个问题。
先自由讲述，再查漏学习、求职、项目、想读的书、兴趣、生活手续、重复责任和等待项。
我的事情是：[口语列出来]。
最早确定期限：[日期或未知]；每天稳定时间：[时间]。
允许读取：[具体资料，没有就只用这条消息]。

请为不同方向编号，给每个方向写一个下一步和完成依据。
总览只管优先级与冲突，具体工作放对应任务。
先展示拆分和资料目录；问我哪些长期方向也要放在左边方便点回去，
哪些暂时只保留在清单。我确定哪些需要独立对话后，再创建。
个人记录保存在本地 private/，公开模板不要填我的真实信息。
今天先帮我开始一件事，完成后保存短进展、证据和下一步。
```

## 之后：左边找任务，文件保当前状态

侧边栏名字使用 `00 总览`、`T01 数据库｜练习`、`T02 作品｜开发` 等可识别标题。可以按项目分组；分组不会自动共享上下文。每个任务保留一个当前入口，阶段结束后保存交接，是否换新对话由用户决定。

上面是**标题格式示例**，编号不对应任何使用者的真实任务。先读自己的任务清单，再核对现有对话。建聊、改标题、移动到分组是三项独立动作：本次会话有相应工具时逐项执行并读回实际标题与入口；没有工具时，把期望标题和首条交接消息交给使用者在 Codex 中手动完成。创建工具返回的 ID 要保存；空对话未出现在搜索结果，只说明可见性尚未核实，不能据此再创建一次。未读回或未获使用者确认，清单记“已发起待核验”（附 ID）或“待本人操作”，不能写“已建好侧边栏”。[入口核对与无工具回退](codex-task-project-method.md#3-建立独立对话留下交接)有完整步骤。

从任务对话回到总览也需要显式回传。任务对话有本人实际结果后，先更新本人授权的同一份 `private/` 清单；若两个对话无法共用文件，就给一段可复制的“任务编号、实际结果及依据、一个下一步”，由使用者贴回总览。投递只在本人实际提交且有回执后登记；对话说“之后回传”本身不算已回传。

### 已经拆好任务，但左边名字还没变

把下面这段发给**那位使用者自己的总览对话**。它只修复入口，不重新访谈，也不套用本仓库示例编号：

```text
这次只处理我现有任务的侧边栏入口，不重做访谈，也不创建重复对话。
请先读我自己的任务清单：[我的 private/tasks.md 路径或我提供的清单]，
核对每个编号的真实任务、已有对话及期望标题；不要套用任何示例的 T02。
我授权你为清单中已确认的现有对话改标题、整理分组，不删除或归档。
旧对话仅在目标、范围和资料适合当前任务时复用；只有标题相近不算核对。
读不到旧对话就标“入口待核对”，不要把它直接定为当前任务入口。
先检查这次会话实际可用的建聊、改标题、移动分组和读回工具。
有工具就逐项执行，再读回实际标题和所在位置；只写已验证的结果。
缺哪项工具，就给我该项可复制的标题、首条交接消息和手动操作步骤，
标记“待我手动落实”；等我确认做完，或你能读回后再标“已验证”。
最后列出：编号、任务、原有入口、期望标题、实际标题、落实状态、
还需要我手动完成什么。不要把建议标题说成已经出现在侧边栏。
```

如果当前会话没有相应管理工具，提示词不能让工具凭空出现。此时使用者在自己的 Codex 客户端操作，并把实际标题回报给总览；清单保留“待本人操作”直至核对。不同使用者的任务编号互不通用。

**如果已经重复创建了空入口，先停。** 暂停新建、归档和下一任务的入口操作；从本轮创建返回值记录每个 ID，核对哪些已有交接消息、哪些仍在运行。搜索不到不能证明不存在，也不能作为自动清理依据。若本次没有可靠的按 ID 核对工具，把这些 ID 和待确认状态交给本人在客户端核对，再决定保留哪一个；不要为检查侧边栏继续写本地接口探针。[官方 app-server 文档](https://developers.openai.com/siwc/token-sharing-open-source/codex-app-server)要求客户端保存创建返回的 `thread.id`，而不是依赖后续搜索推断创建结果。

可复制的止损消息：

```text
先停止本轮的新建、归档、重建和下一任务建聊。
列出每次创建返回的 ID、当前标题、是否已送达首条交接、是否还在运行。
只按这些 ID 或由我在客户端核对；搜索没找到空对话不算创建失败。
保留已有内容的入口，重复项暂不自动清理；无法核对就告诉我
怎么手动查看，并把各入口标为待确认。不要再写接口探针。
```

**已确认的先落实。** 使用者校正了部分方向且已经授权建聊或改名时，只把尚未确定的方向留待下一轮；不要为等待阅读、兴趣等新入口的选择而延后已确认任务。若一个学习方向内部是否拆分尚未决定，先建立已确认的总入口，内部专题以后再拆。当前会话有工具就立即执行能核对的动作并读回；缺工具则在同一轮逐项交付“现有对话或待建、期望标题、首条消息、本人在客户端要做的动作”，让使用者现在就能完成。只说“待落实，等你选完全部方向”并未完成入口交接。[Codex 快捷键参考](https://learn.chatgpt.com/docs/reference/commands)列有新建与重命名对话操作；具体以使用者的客户端为准。

如果总览已陷入反复提问，可直接发送：

```text
这轮先落实我已经确认并授权的任务入口，不等其他候选方向分类。
请读我自己的清单，列出已确认入口与仍待决定的候选；不要重新编号。
对已确认入口，核对旧对话是否适合复用，能建聊、改名或整理就执行并读回。
缺工具时，马上逐项给我准确标题、首条交接消息和手动操作步骤；
我操作并回报前标“待我手动完成”。只问阻碍已确认入口落实的必要问题。
较宽的已确认学习方向先有一个总入口，是否拆分可以以后再定。
最后报告哪些实际完成、哪些需要我操作；不要把候选方向的选择
当作已确认入口的前置条件。
```

当使用者在总览选定一件事时，总览先核对哪个入口真能承接。现有对话若只做过较窄的相关事项，先核对它的目标、资料和阶段；不能仅凭标题扩大成长期任务。能向已核对的任务对话交接时给它明确的下一步；本次会话缺少跨对话工具时，给使用者可复制的任务首条消息，由使用者到该对话继续。总览可以完成紧急的、有界的准备，但应将具体岗位核验、学习或项目执行留给对应任务对话，并把实际结果显式回传。

在本地建立一份 `private/tasks.md`，先由总览串行维护；任务对话回传自己的变化。每个任务再有一份短交接，[复制任务模板](context-templates/task-checkpoint.md)，总览使用[总览模板](context-templates/overview-checkpoint.md)。多个直接写入方需要版本检查和历史记录，避免覆盖。

继续时可以复制：

```text
继续 [任务编号]，先读 [当前交接路径] 和指定总清单。
核对更新时间及来源版本，只读取本阶段需要的资料。
先告诉我目标、已完成、未知和一个下一步；存在冲突先核对依据。
今天我有 [时间]，按我的尝试推进，不把 AI 产物登记成本人完成。
有实际结果后保存短当前状态，旧结果保留到历史，不无限追加摘要。
```

对话越聊越长时，使用[长对话与进度回传协议](codex-context-management.md)。先保存当前状态，再考虑新阶段；清空聊天不是必要步骤。总览看短清单，细节按需查任务对话；无需一直重读全部聊天。

## 方法更新时，让自己的 agent 拉取

在新会话开始或你希望更新方法时检查 main，不必每条消息都查询 GitHub。已在推进的任务继续使用本机状态。可复制：

```text
请检查这个仓库 main 的新版本，先看 git status 和实际远端。
工作区干净且本地 main 可以快进时，使用 git fetch 与 git pull --ff-only；
有未提交修改或分叉时，保留我的工作，先说明需要怎样合并，不 reset、不覆盖。
读取 docs/codex-task-project-evolution.md 和相关文档 diff，
简短说明这次哪些规则变化、哪些没有影响我的当前任务。
把已采用的提交编号写到本机 private/method-version.md。
有记录格式迁移时先保存历史；不复制或上传 private/，不重新安排我的任务。
不同任务对话在下次接续时读取更新后的协作文件，不假设它们自动知道变更。
```

方法变化记入演进记录；仅拉取代码不会自动让已有聊天采用新规则。新用户独立使用的检验办法见[闭环与交付状态](method-delivery-status.md)。
