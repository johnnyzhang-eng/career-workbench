# 从这里开始：把左边的对话变成任务入口

同学版目前只使用 Codex 的总览、侧边栏分组、独立任务对话和本地短记录。不安装或启动小屋子、网页服务、CLI 演示或后台监测。每个人填自己的事情；这里提供协作方法与模板。

## 给已经使用 Codex 的同学

可以把 main 的本页链接交给自己的 Codex，或复制下面的启动消息。允许读取仓库方法，不等于允许读取所有私人文件。

```text
请使用 https://github.com/johnnyzhang-eng/career-workbench 的 main 版本。
如果已有本地 checkout，先检查工作区和实际远端；没有则克隆到我指定的目录。
本次只用 Codex 侧边栏和任务对话，不启动仓库里的应用或演示。
读 AGENTS.md、docs/start-here.md、docs/task-intake-interview.md 和
docs/codex-context-management.md，只使用这里的通用方法。
先和我做渐进访谈，收集我自己的事情，每轮 1–3 个问题。
不要复制作者或其他人的任务，不扫描未指定的私有资料。
在本地 private/ 创建我的清单与短交接；先展示任务拆分让我校正。
我明确要求时再创建独立对话，保留稳定编号与可识别标题。
今天先帮我开始一件事，留下实际结果与下一步。
```

请自行指定本地目录，私人资料保存在自己的 `private/`。无需安装额外 skill 或切换到草稿分支。小屋子继续由作者试验，当前不向同学交付；[交付状态](method-delivery-status.md)区分了这一范围。

## 可以直接转发给同学

这套方法让 Codex 左边的对话变成任务入口：一个总览，每个持续任务一个对话。先和 AI 聊清楚自己的全部事项，再选一件开始。只用 Codex，不用安装其他应用。把下面这段粘到自己的 Codex 即可：

```text
请使用 https://github.com/johnnyzhang-eng/career-workbench 的 main 方法，
先读 docs/start-here.md 和它引用的首次访谈、长对话续接规则。
只用 Codex 的侧边栏、总览和独立任务对话，不启动小屋子或其他程序。
先渐进访谈收集我自己的事情，每轮 1–3 个问题，允许以后补充。
查漏急事、长期项目、重复责任、对外承诺和等待项，确认期限与稳定时间。
展示任务拆分让我校正；确认后我授权你为持续任务创建独立对话、
命名并整理侧边栏。新对话先建入口，不同时启动所有任务。
个人清单和短交接保存在本地 private/，只读取我指定的个人资料。
今天先帮我完成一件小事，有实际结果才记录进展和下一步。
```

当前没有启用“对话太长自动建聊、任务完成自动归档”。长对话先保存短交接，是否换新阶段对话由使用者决定；[续接规则](codex-context-management.md)说明了可用步骤和后续设计。

作者另在自己的实际使用中验证[可选对话检查器](codex-thread-watch.md)：增量读取明确登记的本机日志，仅保留观察元数据。它不属于首次启动要求，只有本人要求监测才启用；模型复核有额外消耗，自动建聊与归档仍未实现。

## 第一次：复制这一段

```text
我想用“一个总览 + 每个持续任务一个对话”组织事情。
先在当前对话和我聊清楚，不立即创建大量对话。
按 task-intake-interview.md 渐进访谈，每轮 1–3 个问题。
先自由讲述，再查漏学习、求职、项目、生活手续、重复责任和等待项。
我的事情是：[口语列出来]。
最早确定期限：[日期或未知]；每天稳定时间：[时间]。
允许读取：[具体资料，没有就只用这条消息]。

请为不同方向编号，给每个方向写一个下一步和完成依据。
总览只管优先级与冲突，具体工作放对应任务。
先展示拆分和资料目录；我确定哪些需要独立对话后，再创建。
个人记录保存在本地 private/，公开模板不要填我的真实信息。
今天先帮我开始一件事，完成后保存短进展、证据和下一步。
```

## 之后：左边找任务，文件保当前状态

侧边栏名字使用 `00 总览`、`T01 数据库｜练习`、`T02 作品｜开发` 等可识别标题。可以按项目分组；分组不会自动共享上下文。每个任务保留一个当前入口，阶段结束后保存交接，是否换新对话由用户决定。

在本地建立一份 `private/tasks.md`，先由总览串行维护；任务对话回传自己的变化。每个任务再有一份短交接，[复制任务模板](context-templates/task-checkpoint.md)，总览使用[总览模板](context-templates/overview-checkpoint.md)。多个直接写入方需要版本检查和历史记录，避免覆盖。

继续时可以复制：

```text
继续 [任务编号]，先读 [当前交接路径] 和指定总清单。
核对更新时间及来源版本，只读取本阶段需要的资料。
先告诉我目标、已完成、未知和一个下一步；存在冲突先核对依据。
今天我有 [时间]，按我的尝试推进，不把 AI 产物登记成本人完成。
有实际结果后保存短当前状态，旧结果保留到历史，不无限追加摘要。
```

对话越聊越长时，使用[长对话与进度回传协议](codex-context-management.md)。先保存当前状态，再考虑新阶段；清空聊天不是必要步骤。总览看短清单，细节按需查任务对话；无需一直重读全部聊天。

## 方法更新时，让自己的 agent 拉取

在新会话开始或你希望更新方法时检查 main，不必每条消息都查询 GitHub。已在推进的任务继续使用本机状态。可复制：

```text
请检查这个仓库 main 的新版本，先看 git status 和实际远端。
工作区干净且本地 main 可以快进时，使用 git fetch 与 git pull --ff-only；
有未提交修改或分叉时，保留我的工作，先说明需要怎样合并，不 reset、不覆盖。
读取 docs/codex-task-project-evolution.md 和相关文档 diff，
简短说明这次哪些规则变化、哪些没有影响我的当前任务。
把已采用的提交编号写到本机 private/method-version.md。
有记录格式迁移时先保存历史；不复制或上传 private/，不重新安排我的任务。
不同任务对话在下次接续时读取更新后的协作文件，不假设它们自动知道变更。
```

方法变化记入演进记录；仅拉取代码不会自动让已有聊天采用新规则。新用户独立使用的检验办法见[闭环与交付状态](method-delivery-status.md)。
