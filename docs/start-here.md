# 用 Codex 管理任务：先让一件事动起来

这套方法只用 Codex 对话和侧边栏；个人事项留在本人本机。**第一次的验收是一个任务产生可核对的结果和下一步**。对话改名、建 Project、写清单只是帮助下次回来，不占用第一次行动的时间。无需安装小屋子、运行本仓库程序或开启监测。

## 已经有任务对话：直接进去做事

如果左侧已有本次要推进的对话，打开它。即使分组没整理好、总览还有候选事项，也先用现有入口完成一次行动。不要重新访谈、新建同名对话、探测本地接口或为了核验侧边栏继续推迟任务。

把下面这段发到**要推进的任务对话**，把方括号换成自己的信息：

```text
这是我当前要推进的 [任务名字]。先读这个对话已有的短交接及我指定的资料；
若缺少影响今天行动的关键事实，只问我一个问题。
今天先完成一个可核对的小步骤：[我想先做的事，或请你给出最小一步]。
请直接推进到实际结果，写清来源、产物或本人作答，以及下一步。
不要在这里继续整理侧边栏、建 Project、重开任务或自动归档。
结束时给我一段可贴回总览的三行回传：任务｜实际结果与依据｜下一步。
```

比如求职任务可以先核对**一个**岗位的官方招聘页、城市、资格和开放状态，再决定要不要准备材料。没有本人实际提交和回执，不登记为已投递。学习任务先让本人尝试一次练习，区分独立完成、带提示完成和 AI 给出的答案。

## 还没有入口：先收集，再只建一个

把本页链接和下面这段一起交给自己的 Codex：

```text
请按本页的首日流程帮我组织自己的事情。这次先找出最需要推进的一项，
每轮问 1–3 个问题；让我校正任务拆分、期限和稳定时间预算。
我确认首项后，只为这一项复用或建立一个任务入口，并完成一次实际行动。
先检查本会话是否已有建聊、改名工具；没有就给我标题和首条消息，
我在客户端手动完成。不要为侧边栏生成接口 schema 或写探针。
不要因为搜索暂时找不到新建空对话就重复创建；保存创建返回的 ID。
其他方向先记在本地清单，稍后再问想读的书、长期项目、学习和兴趣。
第一轮只以实际行动和下一步为完成条件，不追求把整个侧边栏一次排满。
```

已有较窄的旧对话时，先核对其目标和资料是否适合当前任务；只凭标题相近不能复用。新建或改名只做**一次有界能力检查**：工具能用且本人授权就执行并读回；工具缺失或返回状态不明，就记录“待本人操作”或“已发起待核验”，给本人手动步骤，转回任务本身。不要继续研究 app-server、创建重复入口或自动归档。

## 第一次结果之后，再慢慢补全

任务对话用 `任务｜实际结果与依据｜下一步` 回传总览。由总览维护一份本地[空任务清单](context-templates/task-registry.md)；没有共享文件时，使用者把三行回传贴回总览。只记录实际发生的事，不把“已经开聊”“AI 写了”“准备投递”当成本人完成。

后续每轮继续问 1–3 个尚未覆盖的问题：重复责任和等待项、想读的书、长期项目、想学的主题与兴趣。由本人决定哪些需要左侧长期入口，哪些先留清单；**新方向的分类不阻塞当前任务行动**。详细问法见[首次访谈](task-intake-interview.md)。对话很长时再用[短交接与续接规则](codex-context-management.md)，不必清空聊天。

如果已经产生重复对话，先停止创建、归档和重试；保存本轮返回的所有 ID，核对实际消息与客户端可见入口，再决定保留哪一个。[重复入口止损与手动恢复](codex-task-project-reference.md#如果已经重复创建了空入口先停)提供可复制消息。第一次不要为 Project 分组或长对话自动化花时间。

方法更新时只在新会话开始或本人要求时检查仓库 `main`；已有本地 checkout 先检查未提交工作，能快进才拉取，不覆盖个人 `private/`。旧对话不会自动知道新规则，需要在下次接续时明确读取。[完整更新步骤](codex-task-project-reference.md#方法更新时让自己的-agent-拉取)。

进一步了解：[任务与 Project 的区别](codex-task-project-method.md)、[完整提示词与手动恢复](codex-task-project-reference.md)、[当前交付范围](method-delivery-status.md)。小屋子和自动监测不属于同学第一次使用的步骤。
