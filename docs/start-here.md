# 从这里开始：把左边的对话变成任务入口

不必先安装小屋子或克隆仓库。先在自己的 Codex 中整理事情，为持续方向保留独立对话，再用本地短记录接续。这里提供方法与模板，不是自动安装的跨对话监测器。

## 第一次：复制这一段

```text
我想用“一个总览 + 每个持续任务一个对话”组织事情。
先在当前对话和我聊清楚，不立即创建大量对话。
我的事情是：[口语列出来]。
最早确定期限：[日期或未知]；每天稳定时间：[时间]。
允许读取：[具体资料，没有就只用这条消息]。

请为不同方向编号，给每个方向写一个下一步和完成依据。
总览只管优先级与冲突，具体工作放对应任务。
先展示拆分和资料目录；我确定哪些需要独立对话后，再创建。
个人记录保存在本地 private/，公开模板不要填我的真实信息。
今天先帮我开始一件事，完成后保存短进展、证据和下一步。
```

## 之后：左边找任务，文件保当前状态

侧边栏名字使用 `00 总览`、`T01 数据库｜练习`、`T02 作品｜开发` 等可识别标题。可以按项目分组；分组不会自动共享上下文。每个任务保留一个当前入口，阶段结束后保存交接，是否换新对话由用户决定。

在本地建立一份 `private/tasks.md`，先由总览串行维护；任务对话回传自己的变化。每个任务再有一份短交接，[复制任务模板](context-templates/task-checkpoint.md)，总览使用[总览模板](context-templates/overview-checkpoint.md)。多个直接写入方需要版本检查和历史记录，避免覆盖。

继续时可以复制：

```text
继续 [任务编号]，先读 [当前交接路径] 和指定总清单。
核对更新时间及来源版本，只读取本阶段需要的资料。
先告诉我目标、已完成、未知和一个下一步；存在冲突先核对依据。
今天我有 [时间]，按我的尝试推进，不把 AI 产物登记成本人完成。
有实际结果后保存短当前状态，旧结果保留到历史，不无限追加摘要。
```

对话越聊越长时，使用[长对话与进度回传协议](codex-context-management.md)。先保存当前状态，再考虑新阶段；清空聊天不是必要步骤。总览看短清单，细节按需查任务对话；无需一直重读全部聊天。
