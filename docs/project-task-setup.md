# 已有对话：整理为 Project 与任务入口

Codex 的 Project 是包含共享资料和多个聊天的工作范围；任务对话负责各自的结果。一个对话中再做多个可验收的小步骤。这里说的“子任务”是我们对这些任务对话和小步骤的组织约定，不代表客户端有自动拆解、同步进度的原生子任务功能。[官方 Projects and chats 说明](https://learn.chatgpt.com/docs/projects)介绍了 Project、工作目录和独立聊天的关系。

已有任务对话的使用者，把下面整段发在**自己的 `00 总览`**。`Txx` 是编号格式示例，实际编号必须以本人清单和对话内容为准。

```text
请按 https://github.com/johnnyzhang-eng/career-workbench/blob/main/docs/start-here.md
的最新方法，帮我把现在左侧散落的对话整理成“Project → 任务对话”。
这轮从已有聊天出发，不重做全量访谈，也不为了排版创建同名空聊。

先核对我本机清单和左侧实际入口：00 总览、已确认的 Txx 任务对话，
以及我已确认要长期保留的其他方向。只读与这些入口相关
的短交接或最近必要内容；编号含义以我的记录为准，标题相近不等于同一任务。
现有其他 Project 若与这些任务无关，保持不动。

给我一张简短的“Project｜任务对话｜当前实际位置｜希望的位置｜落实状态”表。
优先复用我已有的个人任务 Project；没有时，建立一个属于我的本地
“个人任务”Project，使用我已授权的任务资料目录。Project 下应能看到
00 总览和已确认的持续任务对话；不同资料和权限范围的任务不要硬塞进去。
如果客户端无法把既有对话迁入 Project，保留原对话及其 ID，清单写明它
属于哪个 Project、为何目前仍在“最近”；不要为了层级重建有内容的对话。

只用当前会话提供的项目和聊天管理工具，做一次有界能力检查。有工具就
逐项操作并读回项目归属和标题；缺工具就给我客户端里逐项可做的步骤，
并把状态写成“待我手动操作”。不要生成 app-server schema、写探针、
因为搜索不到就重复建聊，或擅自归档旧入口。不能核验就如实写未知。

整理完当前已确认入口后停止侧边栏工作。后续仍逐轮问我想读的书、长期
项目、学习、兴趣、重复责任和等待项；由我选哪些成为长期入口，
不是现在一次建满。请回到我选定的当前重点任务，在它原有对话里完成一件
可核对的小事，留下实际结果、依据与下一步，再给 00 回传。不把 AI 讨论
或准备工作写成本人已经完成。
```

验收分两件事：先看客户端里是否真的能在相应 Project 下找到该对话，不能就标待操作；再看选定任务有没有实际结果。Project 名字出现在表格里、标题改好或交接写完，都不能代替这两个验收。
