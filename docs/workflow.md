# 完整流程与完成条件

流程完整不等于每一步都自动化。v0.1 负责记录、门槛与闭环，人负责真实信息、判断和对外行动。

| 阶段 | 输入 → 产物 | 完成条件 | 未通过怎么办 |
|---|---|---|---|
| 01 定义目标 | 本人约束 → 本地画像 | 届别、城市、方向、到岗和能力边界由本人核对 | 保留未知，不用同学的画像填空 |
| 02 收集岗位 | 官网或线索 → 唯一岗位记录 | 公司+职位ID或具体链接可区分同名岗位 | 去重；文章中的品牌名单仍是线索 |
| 03 核验匹配 | JD+画像 → 逐项结论 | 城市、学历、届别、年限、开放状态、硬要求、签约主体均有来源和说明 | unknown→hold补查；fail→excluded留因；可重新核验恢复 |
| 04 准备材料 | 已核验JD+事实库 → 材料包 | 简历文件存在，项目表述有证据，不虚构数字或技术栈 | 缺材料返工；材料变动撤销旧确认 |
| 05 人工确认与投递 | 材料包 → 本人确认+实际回执 | 确认针对当前材料版本；真正提交后才登记 submitted | 未确认不能记已投；不把准备完成算投递完成 |
| 06 跟踪与复盘 | 回执/邀请/拒信/面试 → 事件+复盘 | 每次状态有依据；没消息维持原状态 | 超期提醒跟进，不自动判拒绝；拒绝/撤回不删除历史 |
| 07 补练与回流 | 明确缺口 → 练习任务+本人作品 | 留独立尝试、测试和解释证据 | 看懂答案不算掌握；补练后再复测/更新优先级 |

## 状态机（代码强制）

`discovered / hold / excluded / eligible` 可重新核验；准备材料后为 `prepared`，本人确认为 `approved`。重新核验或准备新材料会撤销已有确认。

只有 approved 可以首次记录 submitted；只有 submitted、responded、assessment、interview 可继续记录回应、笔试、面试、offer、rejected、withdrawn。同阶段追加记录允许，用于多轮面试。最终状态不自动回滚；同公司新岗位另建记录。

核验距材料准备、确认或登记提交超过 72 小时会要求重验。这是项目保守默认值，不是公司招聘规定。程序检查核验时间格式、时区和未来时间；不替人证明来源内容真实。

真实投递发生在系统外。如果漏登记导致状态落后，先核对事实再按实际顺序补录；不要伪造确认或回执。v0.1 不支持越级批量迁移历史申请。

## 核验与渠道规则

- 优先读具体官方 JD 与官方指向的 ATS；搜索摘要仅作发现。SPA 可以用正常浏览器读取，不能一概判不可读。
- HTTP 403/404、页面空白、搜索没命中都不能单独证明岗位关闭；检查加载、重试及对照页，必要时标 unknown。
- “招满即止”不是“已招满”；固定截止也不保证 HC 留到最后。优先级综合匹配、截止、滚动风险、志愿限制与准备时间。
- 品牌、招聘服务商、合同主体分字段。猎头推荐不必然是派遣，客户品牌不等于签约雇主。
- 服务商自身“加入我们”与其客户职位库不同。全球 graduate 项目不等于中国项目，更不等于目标届别。
- 福利、转正和稳定性逐岗位核实，不沿用营销文章的绝对承诺。

## 人机职责

人确认约束、真实能力、材料、最终申请和 offer 选择；主负责人做策略、取舍与验收；执行者查询、整理和测试。执行产物必须回来验收，不能停在“agent 做完”。

编码训练禁止直接把执行者生成的答案计入本人能力。技术售前也应训练需求澄清、方案解释、演示、PoC 与必要的代码基础。
