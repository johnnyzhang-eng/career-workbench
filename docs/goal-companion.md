# 本机目标工作台（#34 草案）

本切片把 `GoalStore`、七日首版模板、`GoalDailyBridge` 和 `DailyStore` 接成一个可运行的本机页面。**当前 UI 是验证功能链的临时交互壳，不是最终的布局、美术或角色方案。**默认数据目录是仓库中被忽略的 `private/goal-companion`，不使用账号、云同步、桌面截图、外部素材或收费模型。

```bash
python3 scripts/serve_goal_companion.py --workspace private/goal-companion
```

打开程序打印的 `http://127.0.0.1:8794/`。当前交互壳有三层：`/collapsed` 是房子图标入口；`/compact` 显示常驻房间和最靠前的今日任务；`/` 展开为左侧房间、右侧目标与清单。三层从同一本机状态读取，同一目标 ID 会随展开链接保留。可以把浏览器窗口缩到右上角试用；网页本身不能保证操作系统级置顶、透明度或鼠标穿透，这些属于后续桌面容器验收。

## 首次使用

1. 选择 CET6 或秋招，填写目标、起点、每周可用时间和本人成功标准。本人的目标日期可留空，若填写也不会冒充官方考试日或招聘截止。
2. 选择七日开始日期，生成**待决策**的模板提案。当天已过 20:00 时，日期输入默认次日，仍可由本人改动。逐项检查安排理由、来源、建议时段、完成条件与未知项。模板里的 20:00 是建议时段；当前页面尚无逐项编辑入口，若时段不合适应拒绝此版并改用后续编辑流程，不要误以为页面已验证日程可用。
3. 本人接受或拒绝提案。接受后先显示 `sync_pending`；点击“写入每日清单”，成功后显示 `applied`。若两库有冲突，页面保留 `conflict`，不宣称任务已安排。
4. 对 CET6 练习，填写材料、首次作答和错因／复盘位置，才能记录每日任务完成。这里保存的是本人提供的依据位置，不读取材料内容，不判断掌握程度或考试结果。秋招的岗位核验、材料批准和提交事件仍须走原求职状态机；本页不提供绕过门槛的按钮。
5. 刷新或重启服务后，目标、提案、计划版本、同步状态和每日任务仍由本机 SQLite 事件记录恢复。

房间只反映可信的活动状态。仅计划了任务时，房间保持待机，并以文字提示建议做什么；用户明确“开始行动”后才切换相应动作。“暂停／继续／结束这次行动”控制房间活动声明，不等于每日任务完成。任务仍需原有证据门槛，外部工具线索也不会自动证明掌握、考试通过或岗位已投递。

完整工作台可以由本人选择一张 PNG 或 JPEG 原照（最多 2 MB，边长 64–2048 像素）、在本机查看并删除。文件只保存在指定工作区的 `private_avatar/source.png` 或 `source.jpg`，并以私有目录／文件权限写入；仓库内工作区必须放在被忽略的 `private/` 下。读取原照需要页面令牌，上传和删除还需要同源 Origin、Host、CSRF 与 JSON 内容类型。**这只是未来个人角色生成所需的原照入口，目前不会生成角色，不会把照片发给模型或外部服务，也不会把照片替换成房间精灵。**原照可能带有 EXIF 信息；请在选择照片前自行确认，本入口不会清除元数据。

“今天的行动”按目标时区的现实日期显示当天事项和未完成的以前事项。漏做时只显示温和说明，不扣分、不自动改跨日安排。计划变更、复盘和完整结果联动由 #32 后续接口接入；当前页面明确显示该能力待接，不把 DailyStore 的完成事件假装成 GoalStore 的结果或复盘。

## 需要与用户共同评审的 UI 决策

- 360px 角落视图该首先呈现一项最紧要行动、当日全部任务、进度概览，还是由用户切换；任务理由和证据入口放在哪一层。
- 收起图标、角落小窗、中等展开、完整工作台各层的大小与点击路径，以及透明度、置顶、鼠标穿透在真实桌面中的行为。
- 视觉与角色路线应结合 #20 的同场景 2D／2.5D／3D 运行对照，由用户看过后决定；这里的蓝绿色纸面只是功能测试皮肤。
- 房间里的当前活动、下一行动和清单该如何互相定位，以及用户是否需要在角落视图里看到完整的证据表单。

评审前不把这些临时选择固化成产品规范。原生桌面容器及跨应用窗口行为也未由此 HTML 页面验收。

## 本机访问边界

- 只绑定 `127.0.0.1`，不允许配置 `0.0.0.0`。所有请求核对 `Host`；写请求还要求同源 `Origin`、页面取得的 CSRF 令牌和 JSON 内容类型。页面禁缓存、拒绝被嵌入，使用每次响应生成的 CSP nonce。
- 照片接口只接受格式与图片头都符合要求的 PNG/JPEG 原照，强制体积和尺寸上限；固定文件名避免把本人原始文件名写入日志或仓库。`GET /api/avatar/photo/status` 只返回本机是否已选素材；`GET /api/avatar/photo/image` 还需要页面令牌；`POST /api/avatar/photo` 和 `POST /api/avatar/photo/delete` 受相同写入门槛保护。
- 每个请求重新打开并关闭 SQLite 连接，避免在线程间共享连接。服务使用标准库单线程 `HTTPServer`；两个页面对同一事件存储读取。Goal/Daily 双库尚非原子事务，`sync_pending` 可重试，且绝不把冲突遮成成功。
- 令牌保护的是从浏览器网页发起的写入，不能阻止本机上已获同等文件权限的进程直接修改 SQLite。请只在可信本机运行，不转发端口到公网；个人记录只留在私有目录。
- 自定义目标的手动建任务、任意目标 AI 规划、日程编辑、桌面置顶/透明度，以及 #32 结果复盘桥接仍需后续迭代。

## 核验

```bash
python3 -m unittest tests.test_goal_web -v
python3 -m unittest discover -s tests -v
python3 scripts/check_privacy.py
```

HTTP 测试覆盖虚构 CET6 目标 → 提案未生效 → 本人接受 → 待同步 → 七任务已安排 → 拒绝缺首次作答 → 保存完整练习依据 → 重启恢复；还覆盖秋招拒绝提案以及 Host、Origin、CSRF 和内容类型边界。测试不会访问外部网站或真实个人工作空间。
